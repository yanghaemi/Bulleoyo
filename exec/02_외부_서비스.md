# 외부 서비스 연동 정보

> SSAFY 최종 산출물. 값은 적지 않는다 — 보관 위치만 남긴다.

## Web3Auth (Plug-and-Play Modal v10)

- **용도**: 소셜 로그인(구글·페이스북·카카오) → 비수탁 지갑 생성/서명의 기반이 되는 신원 증명(idToken). C-01 로그인 화면이 이 흐름을 쓴다.
- **가입·설정에 필요한 것**: Web3Auth 대시보드 프로젝트, Client ID, 허용 도메인(Whitelist)에 `https://j15b204.p.ssafy.io`(운영)·`http://localhost:5173`(로컬 프론트)를 등록.
- **코드/설정 위치**:
  - 프론트: `VITE_WEB3AUTH_CLIENT_ID`(빌드 시점 ARG, `.env.example`)
  - 백엔드: `WEB3AUTH_CLIENT_ID` 환경변수 → `backend/src/main/resources/application.yml`의 `b204.web3auth.client-id`로 매핑(`Web3AuthProperties`, prefix `b204.web3auth`). idToken JWKS 검증은 `b204.web3auth.jwks-uri`(기본 `https://api-auth.web3auth.io/jwks` — Sapphire Devnet), `iss` 클레임 검증은 `b204.web3auth.issuer`(기본 `https://api-auth.web3auth.io`)로 한다. **운영에서는 이 두 값이 기본값으로 고정이다** — `docker-compose.yml`의 backend `environment`가 `WEB3AUTH_CLIENT_ID`만 넘기므로 `B204_ENV`에 `WEB3AUTH_JWKS_URI`·`WEB3AUTH_ISSUER`를 넣어도 컨테이너에 닿지 않는다. 바꾸려면 compose `environment`에 먼저 추가한다(`.env.example` 82행 주석과 같은 내용).
- **비밀 값 보관 위치**: `WEB3AUTH_CLIENT_ID` 값은 Jenkins Credentials `B204_ENV`. 프론트의 `VITE_WEB3AUTH_CLIENT_ID` 는 **따로 두지 않는다** — Jenkins `Build` 스테이지가 `B204_ENV` 의 `WEB3AUTH_CLIENT_ID` 를 읽어 `--build-arg` 로 넘긴다(`Jenkinsfile:342·372`). Client ID 자체는 공개 식별자에 가깝지만 저장소에는 값을 커밋하지 않는다.

## Kaia Kairos 테스트넷

- **용도**: 서비스의 유일한 실체인 네트워크(백업 체인 없음, 기술 스택 v3 §1). YoYo 코인·RevenueSplitter 컨트랙트가 배포돼 있다.
- **가입·설정에 필요한 것**: 가스(KAIA)를 받을 Kairos Faucet — **(확인 필요: Faucet URL)**. 운영 지갑은 역할이 셋으로 나뉜다 — OPERATOR(수수료 대납·정산 tx 전송), MINTER(코인 발행), ADMIN(콜드 키, 배포·pause·rotate 전용, 서버에 올리지 않음).
- **코드/설정 위치**:
  - RPC: `https://public-en-kairos.node.kaia.io`, chainId `1001` — `KAIA_RPC_URL`/`KAIA_CHAIN_ID`(백엔드), `VITE_KAIA_RPC_URL`/`VITE_KAIA_CHAIN_ID`(프론트)
  - 익스플로러: `https://kairos.kaiascan.io`
  - 배포된 주소(공개값): `blockchain/deployments/kairos.json` — `contracts.YoYo.address`·`contracts.RevenueSplitter.address`, 역할 주소는 `roles.operator`·`roles.minter`·`roles.admin`
  - 컴파일러·네트워크 설정: `blockchain/hardhat.config.ts`
- **비밀 값 보관 위치**: `OPERATOR_PRIVATE_KEY`·`MINTER_PRIVATE_KEY`는 Jenkins Credentials `B204_ENV`. `ADMIN_PRIVATE_KEY`(콜드 키)는 별도 Jenkins Secret text `ADMIN_PRIVATE_KEY`로, 컨트랙트 배포·MINTER 로테이션 스테이지에서만 읽는다. 서버 `.env`·저장소 어디에도 평문으로 두지 않는다.

## Kaia Wallet (브라우저 확장)

- **용도**: 회원이 자체 지갑(Web3Auth가 아닌 외부 지갑)으로 등록할 때 쓰는 브라우저 확장 지갑. 등록은 서버가 발급한 챌린지에 서명하는 방식(C-05 지갑 등록 화면 선택 카드 ②)이다.
- **가입·설정에 필요한 것**: 사용자가 브라우저에 확장 설치. 서비스 쪽 별도 가입·API 키는 없다.
- **코드/설정 위치**: 프론트 지갑 등록 흐름(C-05), 백엔드 챌린지 발급/서명 검증 API(API-wallet-03·04).
- **비밀 값 보관 위치**: 없음(사용자 브라우저의 개인키, 서비스가 보관하지 않음).

## WebAuthn(패스키)

- **용도**: 결제·규칙 동의·보증금·정산 조기 동의·정산금 지급 다섯 동작의 본인 확인(step-up). 기본은 꺼져 있다.
- **가입·설정에 필요한 것**: 별도 외부 가입 없음(브라우저·OS 표준 WebAuthn API). 서버가 RP(Relying Party) 역할을 한다.
- **코드/설정 위치**: `STEP_UP_ENABLED`·`WEBAUTHN_RP_ID`·`WEBAUTHN_ORIGINS` 환경변수 → `application.yml`의 `b204.webauthn.enabled`·`b204.webauthn.rp-id`·`b204.webauthn.origins`(+ `b204.webauthn.step-up-ttl` 기본 120초, `WebAuthnProperties` prefix `b204.webauthn`). DB는 `V14__webauthn_credential.sql`.
- **비밀 값 보관 위치**: 이 항목의 환경변수 자체는 비밀이 아니다(도메인·on/off 스위치). `B204_ENV`로 배포되는 것은 동일.

## Mattermost

- **용도**:
  - Jenkins 빌드 성공/실패 알림
  - 운영 알림(서버 결함 revert·발행량 halt 전환) — 백엔드가 직접 전송
  - Alertmanager 알림(모니터링 스택)
  - GitLab MR 생성/머지/닫힘·MR 코멘트 알림(`b204-notify`, MR 작성자 @태그) — 자동 리뷰 봇 코멘트는 "🤖 자동 리뷰"로 표시
- **가입·설정에 필요한 것**: Mattermost 채널 + incoming webhook 발급.
- **코드/설정 위치**:
  - Jenkins 빌드 알림·운영 알림(`ALERT_WEBHOOK_URL`): `Jenkinsfile`
  - Alertmanager: `exec/monitoring/alertmanager.yml`
  - MR 알림: `exec/jenkins/notify/`
- **비밀 값 보관 위치**: Jenkins Secret text `MATTERMOST_WEBHOOK`(빌드 알림·운영 알림 공용). MR 알림 웹훅과 GitLab 웹훅 Secret token은 서버 `~/jenkins/.env.notify`(미커밋). Alertmanager 웹훅은 서버 `~/monitoring/secrets/mattermost_url`.

## GitLab (lab.ssafy.com)

- **용도**: 소스 저장소, MR 생성 시 Jenkins 웹훅 트리거, MR 코멘트로 자동 리뷰 봇 결과 게시.
- **가입·설정에 필요한 것**: 프로젝트 웹훅 등록(Merge request events · Comments), 자동 리뷰 봇용 API 토큰.
- **코드/설정 위치**: 자동 리뷰 봇 `exec/review/mr-review.sh`·`exec/review/prompt.md`.
- **비밀 값 보관 위치**: Jenkins Credentials `GITLAB_REVIEW_TOKEN`(리뷰 봇 API 접근), `CLAUDE_CODE_OAUTH_TOKEN`(리뷰 봇이 Claude Code를 호출).

## Let's Encrypt

- **용도**: `j15b204.p.ssafy.io` HTTPS 인증서.
- **가입·설정에 필요한 것**: certbot으로 도메인 소유 검증 후 발급.
- **코드/설정 위치**: 인증서 경로는 `/etc/letsencrypt/live/j15b204.p.ssafy.io/`를 `exec/nginx/j15b204.p.ssafy.io.conf`가 참조.
- **비밀 값 보관 위치**: 해당 없음(인증서·키는 서버 로컬 파일, 갱신은 systemd 타이머가 자동 수행).

## Jira · Notion · ERD Cloud

- **용도**: 협업 도구 — 이슈 관리(Jira), 팀 문서 사본(Notion, 정본은 저장소 `docs/`), ERD 다이어그램 정본(ERD Cloud).
- **가입·설정에 필요한 것**: 팀 계정 초대.
- **코드/설정 위치**: ERD Cloud 다이어그램 링크는 루트 `README.md` §8(문서)에 있다. ERD Cloud 다이어그램 ID는 `docs/design/16_ERD_v6.md` 상단(`kpxqsmzYGNrskWTMF`).
- **비밀 값 보관 위치**: 해당 없음(개인 계정 로그인).

## ML 실험 서버 (선택, 운영 경로 아님)

- **용도**: 추천 2차 실험(임베딩 기반)용 — 팀원 노트북 GPU(RTX 4050)에서 Ollama(Qwen3 4B·bge-m3) + FastAPI를 돌리고 Tailscale로 접근. **서비스는 이 서버 없이 동작한다** — 1차는 SQL 장르 매칭(콜드스타트 추천, `V13__recommendation.sql`)이며 운영 요청 경로에 포함되지 않는다.
- **가입·설정에 필요한 것**: 팀원 개인 노트북 + Tailscale 네트워크 참가.
- **코드/설정 위치**: `docs/ml/RECOMMENDATION_EXPERIMENTS.md`, `docs/superpowers/specs/2026-09-22-recommendation-design.md`.
- **비밀 값 보관 위치**: 해당 없음(운영 배포에 관여하지 않음).

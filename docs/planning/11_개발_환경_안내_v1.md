### 2.3 브랜치·커밋·푸시 (컨벤션 §3)

```bash
git switch develop && git pull
git switch -c feat/be/ticket          # feat/{be|fe|bc}/{도메인}, Jira 키 넣지 않음
git add -p                            # git add . 금지 — .env 실수 방지
git commit -m "feat: 예매 시 관람 목적 팀 선택 저장" -m "S15P21B204-19"
git push -u origin feat/be/ticket     # 출력된 링크로 MR → develop
```

- develop이 앞서가면 `git fetch && git rebase origin/develop` → `git push --force-with-lease` (내 브랜치만)
- 머지는 GitLab MR 버튼으로만. 리뷰어는 그 도메인을 안 쓴 사람
- 커밋에 `.env`·`application-local.yml`·`.env.local`·`*.pem`·개인키가 들어가면 히스토리를 지워도 유출로 본다. 키 교체 필요

### 2.4 환경변수 이름 계약

`.env.example`이 정본이다. 백엔드·프론트·compose·CI 네 곳이 같은 이름을 쓴다. 이름을 바꾸려면 네 곳을 함께 고치고 인프라 담당에게 알린다.

- 백엔드: `DB_URL` `DB_USERNAME` `DB_PASSWORD` `REDIS_HOST` `REDIS_PORT` `JWT_SECRET` `OPERATOR_PRIVATE_KEY` `MINTER_PRIVATE_KEY` `KAIA_RPC_URL` `KAIA_CHAIN_ID` `CONTRACT_YOYO_ADDRESS` `CONTRACT_SPLITTER_ADDRESS` `WEB3AUTH_CLIENT_ID`
- 프론트(빌드 시점): `VITE_API_BASE_URL` `VITE_WEB3AUTH_CLIENT_ID` `VITE_KAIA_RPC_URL` `VITE_KAIA_CHAIN_ID` `VITE_CONTRACT_YOYO_ADDRESS` `VITE_CONTRACT_SPLITTER_ADDRESS`
- 운영 값은 Jenkins Credentials에만 있다. 컨트랙트 주소는 Jenkins가 `blockchain/deployments/kairos.json`에서 읽는다

### 2.5 API 문서(Swagger) 보는 법

API 계약의 정본은 `docs/design/06_API_명세서_v6.md`이고, 같은 내용을 기계 판독용으로 옮긴 `docs/design/api/openapi.yaml`을 Swagger UI로 볼 수 있다. 세 곳 중 편한 곳을 쓴다.

| 위치 | 주소 | 접근 | 비고 |
|------|------|------|------|
| 서버 | https://j15b204.p.ssafy.io/docs/ | 브라우저 팝업에 아이디 `b204dev` · 비밀번호는 이강륜에게 (채팅에 적지 않는다) | develop 머지마다 Jenkins가 자동 갱신. 발표·컨설턴트 공유용 |
| GitLab | 저장소 → `docs/design/api/openapi.yaml` → 상단 "Display rendered file" | 저장소 멤버 로그인 | 브랜치별로 볼 수 있음. MR 리뷰 때 편함 |

- 서버 문서가 옛 버전이면 Jenkins `develop` 최신 빌드 로그에 "API 문서 갱신" 줄이 있는지 확인. 없으면 이강륜에게.

### 2.6 Claude Code 하네스 (저장소에 포함)

저장소 루트의 `CLAUDE.md`와 `.claude/` 폴더에 팀 공용 Claude Code 설정이 들어 있다. `develop`을 pull하고 저장소 루트에서 Claude Code를 열면 자동으로 적용된다. 따로 설치할 것은 없다.

| 구성 | 하는 일 | 이렇게 말하면 된다 |
|------|---------|---------------------|
| be-dev · fe-dev · contract-dev · infra-dev | 파트별 구현 에이전트. API v6·ERD v5·ABI를 계약으로 삼고 명세 밖은 만들지 않는다 | "ticket 도메인 0층 API 만들어", "정산 규칙 화면 붙여", "RevenueSplitter에 halt 추가" |
| integration-qa | 백엔드 응답 ↔ 프론트 타입, ABI ↔ 래퍼·RLP, ERD ↔ Flyway 교차 비교 | "명세대로 됐는지 확인", "프론트·백 맞는지 QA" — 도메인 하나 끝나면, MR 전에 |
| doc-writer | docs/ 문서 개정(v2 분리)·노션 페이지 | "이 결정 문서로 정리해", "노션에 써줘" |
| b204-stack 스킬 | 스택 확정값과 함정(flyway-mysql 누락, okhttp 충돌, ethers-ext 서브패스, Java 21 금지) | 빌드·기동 오류가 나면 먼저 "b204-stack 확인해줘" |

규칙 네 가지.

- 코드는 명세의 결과물이다. 명세(API v6·ERD v5·화면 v6)에 없는 것을 만들려면 명세를 먼저 고친다. 에이전트도 이 규칙을 따른다.
- 에이전트 정의(`.claude/agents/*.md`)나 스킬을 바꾸려면 MR로. 각자 로컬에서만 쓰는 설정은 `CLAUDE.local.md`에 두면 커밋되지 않는다.
- `_workspace/`는 에이전트 중간 산출물이다. 커밋하지 않는다(gitignore에 있음).
- 모델은 계획·검증이 Fable, 코드 작성이 opus, 문서가 sonnet으로 정해져 있다(`CLAUDE.md` 모델 정책). 바꾸고 싶으면 이강륜에게.

Claude Code를 쓰지 않는 사람에게는 영향이 없다. `.claude/`는 그냥 폴더다.

## 3. 파트별 할 일과 계약

### 3.1 양해미 — 백엔드 프로젝트 초기화 (W3 화요일까지)

- [ ] Spring Boot 3.5.x · Java 17 · Gradle 프로젝트를 `backend/`에 생성. **`gradlew` 래퍼를 커밋**한다 — Jenkins가 `backend/gradlew` 존재로 테스트·빌드를 켠다
- [ ] **start.spring.io가 지금 Boot 3.5.x를 만들어 주지 않는다(9/7 확인).** 수동 작성 또는 이강륜의 PoC 4 프로젝트를 받아서 시작. 체인 의존성은 `io.kaia:web3j-ext:v2.0.7`(v 접두) + `org.web3j:core:4.9.8` 명시 + `okhttp:4.12.0`, nexus 플러그인 exclude — 정확한 블록은 `.claude/skills/b204-stack/references/backend.md`
- [ ] 스타터: Web · Validation · Data JPA · Security · oauth2-jose · Data Redis · Actuator · **Flyway 11 + `flyway-mysql`** (빠지면 `Unsupported Database: MySQL 8.0`로 기동 실패)
- [ ] `application-example.yml` 커밋, `application-local.yml`은 gitignore. 프로파일 `local`(로컬 DB)·`prod`(서버). 변수는 `${ENV:기본값}` 형태로 참조
- [ ] **체인 변수(OPERATOR·MINTER 키, 컨트랙트 주소)가 비어 있어도 기동돼야 한다.** 빈 값이면 체인 빈을 비활성 또는 지연 초기화. 키 없는 팀원이 API 개발을 해야 한다
- [ ] `GET /actuator/health` 열기 — compose 헬스체크가 이걸 본다. 컨트롤러 매핑은 `/api/v1/...`
- [ ] Flyway V1 = ERD v5 SQL(`docs/design/12_ERD_v5_import.sql`). `ddl-auto=none`
- [ ] Dockerfile은 `./gradlew bootJar` 산출물 jar 1개를 전제한다. 멀티 모듈로 가면 인프라 담당에게 알릴 것
- [ ] 로컬 확인: `./gradlew bootRun --args='--spring.profiles.active=local'` → health 200

### 3.2 강병구 — 프론트 프로젝트 초기화 + Web3Auth

- [ ] Vite 7 · React 19 · TS strict · pnpm 프로젝트를 `frontend/`에 생성. `pnpm-lock.yaml` 커밋 필수 — `frontend/Dockerfile`이 `COPY package.json pnpm-lock.yaml`을 전제한다. 없으면 이미지 빌드 실패. `.nvmrc`에 22
- [ ] `package.json`에 `"packageManager": "pnpm@<정확한 버전>"` 필수 — Jenkins 이미지는 corepack enable만 돼 있어 이 필드로 pnpm 버전을 결정한다. 없으면 CI에서 pnpm 버전이 불확정
- [ ] `vite.config.ts` `server.proxy`: `/api` → `http://localhost:8080`. 그래야 `VITE_API_BASE_URL=/api` 하나로 로컬·운영이 같다
- [ ] `package.json`에 `lint`·`test`·`build` 스크립트 — Jenkins가 이 셋을 부른다. test는 초기에 `vitest run --passWithNoTests`로 두어도 됨
- [ ] 환경변수는 `frontend/.env.local`(gitignore)에 `VITE_*`. 코드에서 컨트랙트 주소·chainId는 `shared/config` 한 곳
- [ ] `VITE_*` 6개는 빌드 시점 ARG — 값이 바뀌면 재빌드. 컨트랙트 주소는 `kairos.json` 커밋 전까지 빈 문자열이므로 코드에서 빈 값 처리(주소 없으면 체인 기능 비활성 표시)
- [ ] **Web3Auth 대시보드** (`dashboard.web3auth.io`): Sapphire Devnet 프로젝트 생성 · Platform Web · Whitelist에 `https://j15b204.p.ssafy.io`와 `http://localhost:5173` 둘 다 · Client ID를 이강륜에게 전달(Jenkins Credentials `WEB3AUTH_CLIENT_ID`)
- [ ] PoC 1~3 (스택 v2 §5): Web3Auth v10 × React 19 로그인, ethers-ext로 대납 RLP, Kaia Wallet 동일 RLP. **카카오는 Web3Auth 기본 제공자에 없다** — 커스텀 인증이 필요한지 PoC 1에서 확인

## 4. 배포·운영은 이렇게 돈다

- 도메인 브랜치 → MR → `develop` 머지 → 약 5분 후 https://j15b204.p.ssafy.io 반영. 사람이 서버에 들어갈 일 없음
- 배포가 깨지면 이강륜이 이전 이미지 태그로 롤백한다. 팀원은 MR을 revert하거나 수정 커밋만 올리면 된다
- 서버 로그가 필요하면 이강륜에게 요청. SSH 계정은 인프라 담당만 가진다
- `/actuator/`는 외부에서 404가 정상. 헬스체크는 서버 안에서만
- 빌드 진행·로그는 https://j15b204.p.ssafy.io/jenkins/ 에서 본다. 계정은 이강륜이 발급
- **MR을 올리면 자동 리뷰 노트가 달린다**(🤖 자동 리뷰, 2026-09-09부터). Jenkins MR 빌드가 Claude Code로 diff를 검토해 "머지 전에 고칠 것 / 제안 / 확인한 것"을 남기고, 같은 MR에 푸시하면 그 노트를 갱신한다. 참고용이다 — 머지 판단은 사람 리뷰어가 한다. 틀린 지적은 답글로 남겨두면 프롬프트(`exec/review/prompt.md`)에 반영한다

## 5. 자주 나는 문제

| 증상 | 원인 | 해결 |
|------|------|------|
| `You are not allowed to push code to protected branches` | develop·master에 직접 push | 브랜치 만들어 push 후 MR |
| `rejected ... non-fast-forward` | 원격이 앞서감 | `git pull --rebase` 후 push |
| `Authentication failed` | 비밀번호 사용 또는 토큰 만료 | PAT 재발급, 자격 증명 저장소 정리 |
| `bind: address already in use` 3306 | 노트북에 MySQL이 켜져 있음 | 로컬 MySQL 중지, 또는 compose 포트 13306으로 |
| `Unsupported Database: MySQL 8.0` | `flyway-mysql` 누락 | 의존성 추가 |
| web3j 관련 NoSuchMethod | Java 21 또는 okhttp 충돌 | Java 17 확인, `b204-stack` 참조 문서 |
| MR 머지 버튼 잠김 | 파이프라인 실패 또는 승인 0 | Jenkins 빌드 로그 확인, 리뷰어 지정 |
| 백엔드 테스트 3건 `initializationError`(Testcontainers), `Could not find a valid Docker environment` | Docker 엔진 29.x가 낮은 API 버전 요청을 400으로 거부(`docker version`의 `Server MinAPIVersion` 1.40+) | `DOCKER_API_VERSION=1.44 ./gradlew test`. Jenkins는 compose에 이미 반영됨 |
| `./gradlew: Permission denied` | 실행 비트 없이 커밋된 적 있음(9/7 수정) | `git pull` 후에도 나면 `chmod +x backend/gradlew`, 또는 `bash gradlew …` |

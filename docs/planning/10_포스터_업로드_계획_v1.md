# 포스터 업로드 계획 v1

- 작성 2026-09-06 · 상태: **계획(1층, W4 착수)** · 작성 이강륜
- 근거: API v6 `posterImageUrl`(06_API_명세서_v6.md:1471), ERD v5 `performance.poster_image_path`(12_ERD_v5_import_mvp.sql:159), 요구사항 v6 컷 라인(포스터 업로드 미포함)
- 결정: 0층은 URL 입력(현 명세) 유지, 업로드는 1층. MinIO·S3는 채택하지 않음(단일 EC2, 서버 디스크 + Nginx 정적 서빙).

---

## 1. 배경과 결정

- 현 명세: 공연 생성·수정이 `posterImageUrl`(https URL 문자열, 선택)을 받는다. 업로드 엔드포인트는 없다. ERD는 `poster_image_path VARCHAR(500)`.
- 0층: 그대로 둔다. 공연자가 외부 이미지 URL을 입력한다.
- 1층: 폼 안에서 이미지 선택 → 즉시 미리보기·업로드 → 저장 시 URL만 전송한다. URL 붙여넣기 입력칸은 제거해 경로를 하나로 통일한다.
- 저장소 선택: 서버 디스크 바인드 마운트 + Nginx 정적 서빙. MinIO는 컨테이너·자격 증명·SDK가 추가로 필요하고 단일 서버에서 S3 호환이 필요 없어 배제한다. S3는 AWS 계정·비용이 필요해 배제한다. 서버가 2대 이상이 되면 S3로 전환한다.

## 2. 사용자 흐름

1. 공연 생성 폼 포스터 칸 탭 → 모바일 갤러리·카메라 / PC 파일 선택·드래그
2. 선택 즉시 미리보기 + 업로드 시작, 진행 표시
3. "바꾸기"로 재선택
4. 나머지 입력 후 저장 — 포스터는 이미 서버에 있어 저장 즉시 완료

근거: 저장 시점 업로드는 폼 저장을 느리게 하고 실패 범위를 넓힌다.

## 4. 단계별 결정

**명세(API v7)**: `POST /api/v1/files` multipart 필드 `file`, 인증 필수(공연자). 응답 `201 {code:"SUCCESS", data:{url,width,height,bytes,contentType}}`. 제한 5MB, `image/jpeg`·`image/png`·`image/webp`, 파일 시그니처로 판정. 에러 `413 FILE_TOO_LARGE`, `400 FILE_TYPE_NOT_ALLOWED`. 저장 경로 `uploads/p/{yyyyMM}/{uuid}.{ext}`, URL `{PUBLIC_BASE_URL}/uploads/p/...`. 공연 API는 무변경. 백엔드 환경변수 `UPLOAD_DIR`(기본 `/app/uploads`)·`PUBLIC_BASE_URL` 추가, `.env.example` 갱신.

**인프라**: compose 백엔드 바인드 마운트 `/home/ubuntu/app/uploads:/app/uploads`(Nginx가 같은 경로를 읽어야 해서 named volume 대신 바인드). Nginx `location /uploads/ { alias /home/ubuntu/app/uploads/; expires 1y; add_header Cache-Control "public, immutable"; }`(uuid 파일명이라 영구 캐시가 안전하다). `/api/`에 `client_max_body_size 10m`. 롤백·재배포와 무관하게 파일을 유지하고, 서버 재구축 시 `~/app/uploads`를 백업 대상으로 둔다. 로컬 `local` 프로파일은 Spring이 `/uploads/**`를 `UPLOAD_DIR`에서 정적 서빙한다(Nginx 없이 미리보기).

**백엔드**: `FileController` + `FileStorageService`(저장·시그니처·`ImageIO`로 크기 확인). 라이브러리 추가 없음. `file` 테이블 없음. 에러는 `@RestControllerAdvice` 규격을 따른다. 테스트: 정상, 6MB 거부, png 확장자에 GIF 내용 거부.

**프론트**: `shared/ui/PosterPicker`(빈 카드 → `accept="image/*"` → 미리보기 → 진행 → URL 세팅, 바꾸기). 전송 전 canvas 압축(긴 변 1600px, JPEG 0.8, 라이브러리 없음, 약 20줄). `useUploadFile` mutation. 실패 시 토스트, 폼은 유지. 포스터 없으면 기본 이미지.

**QA**: 응답 shape ↔ 프론트 타입, 에러 코드 매핑, Nginx 경로 ↔ 백엔드 URL 200, 압축 후 5MB 이내.

## 5. 완료 기준

- 폰 8MB 사진 → 2초 안에 미리보기·업로드 완료
- 6MB 원본 비압축 전송 → 413, GIF를 png로 위장 → 400
- 재배포·롤백 후 기존 포스터 URL 200
- 로컬에서 Nginx 없이 동일 흐름 동작

## 6. 알고 가는 한계

- 고아 파일(업로드 후 공연 미저장) 방치. 필요 시 P2 "24시간 미참조 파일 삭제 스케줄러"
- 디스크 상한 없음. 5MB × 수백 건 = 수 GB, 15G 서버에서 문제없음. 런북에 `du -sh ~/app/uploads` 점검
- 서버 2대 이상이면 S3 전환

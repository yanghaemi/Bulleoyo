## 3. 주차 목표와 판정

| 주 | 목표 | 판정 기준 (금요일) |
|---|---|---|
| W3 | PoC 6항목 통과 + 0층 세로축 Kairos 관통 | 관객 계정 하나로 로그인 → 결제 → 입장 → release → 검증 페이지가 **실제 tx**로 끝남 |
| W4 | 1층 전체 + 예외 경로 | 서명 거부·환불·이의제기·공연 취소가 화면에서 됨 |
| W5 | 리허설 2회, 컷 정리, 발표 | 리허설에서 실패한 단계는 컷 라인으로 내림 |

**W3 금요일에 세로축이 안 뚫리면 W4 계획을 바꾼다.** 1층으로 가지 않고 전원이 세로축에 붙는다. 대납 경로가 막혔으면 컷 라인 ③(외부 지갑 제외)부터 적용한다.

AI 네이티브로 W3에 여유가 생기면 1층을 앞당기지 않고 **대납 경로 안정화 · Testcontainers 테스트 · chain_job 재시도 검증**에 쓴다. 시연에서 깨지는 건 화면이 아니라 tx다.

### 부하 감각

| 사람 | 몫 | 비고 |
|---|---|---|
| 신현경 | 화면 31개 마크업 + 토큰 | 마크업만 맡으면 감당 가능. 로직은 전부 강병구 |
| 강병구 | 화면 로직 31개 + 지갑 연동 | **가장 무거움.** PoC 1~3은 오민근과 페어, 예외 UX는 양해미가 API 응답 코드로 받침 |
| 양해미 | 도메인 9개 CRUD·상태 전이 + entry | 건수는 많지만 AI 네이티브로 가장 빨리 나오는 영역 |
| 오민근 | 컨트랙트 + coin·settlement | 불확실성이 가장 큼. 일반 CRUD는 주지 않음 |
| 이강륜 | 인프라 3일 + 서버 체인 모듈 + verify | 인프라가 끝나는 W3 중반부터 체인에 전념 |

강병구 과부하 신호가 보이면 **신현경이 검증 페이지(V-01·V-02) 로직까지** 맡는다. 검증 페이지는 지갑 연동이 없어 떼어내기 쉽다.

## 5. 체인 분담 상세 (오민근 ↔ 이강륜)

절단면은 **컨트랙트(온체인)** 와 **서버 체인 모듈(오프체인에서 체인을 호출)** 이다.

| | 오민근 | 이강륜 |
|---|---|---|
| 담당 | YoYo·RevenueSplitter Solidity · Hardhat 테스트(정산 공식·halt·환불·역할) · Kairos 배포 스크립트 · ABI·이벤트·revert 코드 설계 | web3j-ext 연동 · `chain_job` 워커(nonce 직렬화·재시도·멱등) · fee payer 서명·전송 · receipt·이벤트 검증 · DB↔체인 대사 · 잔액 캐시 갱신 |
| 겸하는 도메인 | coin(발행 어댑터 MockIssuer) · settlement API | verify API(재계산 데이터) · 컨트랙트 배포 파이프라인·키·파우셋 |
| PoC | 2·3(프론트 RLP 생성, 강병구와 페어) | 4·5·6(web3j-ext 기동 · RLP 디코드→fee payer 서명→전송 · Flyway ENUM) |
| 브랜치 | `feat/bc/contract` | `feat/be/chain` |

**둘 사이 계약 = ABI + 이벤트 시그니처 + tx 타입.** W3 화요일까지 오민근이 컨트랙트 인터페이스(함수·이벤트·revert 코드)를 고정하고 Kairos에 1차 배포한다. 이강륜은 그 주소로 서버 모듈을 붙인다. 컨트랙트 로직이 바뀌어도 인터페이스가 같으면 서버는 건드리지 않는다.

### 핑퐁 방지

1. **대납 실패는 셋이 같이 본다.** 발신자 서명 RLP(프론트·컨트랙트 인자) / fee payer 서명(서버) / 컨트랙트 revert 중 어디인지 receipt 하나로 판정한다. PoC 5는 오민근·이강륜·강병구가 같은 시간에 붙는다.
2. **서로의 영역을 한 번은 손댄다.** 오민근은 서버 체인 모듈 리뷰어, 이강륜은 Hardhat 테스트를 로컬에서 돌릴 수 있게 컨트랙트 저장소를 둔다. 한쪽이 막히면 바로 대체 가능해야 한다.

### 이강륜 준비 순서 (인프라 세팅과 병행)

1. 08 블록체인 설명 §5·§7 → Kaia web3j-ext 문서의 fee-delegated smart contract execution 예제를 로컬 실행
2. Boot 3.5 빈 프로젝트 + `io.kaia:web3j-ext` v2.0.7 → 기동(okhttp 충돌 확인) → Kairos `balanceOf` 호출
3. 오민근 1차 배포 주소로 `mint` tx 전송 → receipt·이벤트 파싱
4. 대납 경로(PoC 5)

1~3은 컨트랙트가 나오기 전에도 Kairos의 아무 ERC-20으로 가능. W3 수요일쯤 4에 도달하는 것이 목표.

## 6. 규칙

1. **경계는 도메인.** 브랜치는 도메인 단위(컨벤션 §3). 한 도메인의 API·화면을 다른 사람이 만들 때 응답 스키마는 API v6가 계약이다. 명세 밖으로 나가면 명세를 먼저 고친다.
2. **W3 금요일 판정**에서 세로축이 안 뚫리면 1층으로 가지 않는다(§3).
3. **발표 Q&A는 오민근·이강륜이 체인 질문을 받는다.** 발표자(Jira -32 양해미)와 별개로 정한다.

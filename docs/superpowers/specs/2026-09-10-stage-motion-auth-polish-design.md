# 무대형 인터랙션·로그인·브랜드 정합성 설계

## 1. 목적과 승인 범위

2026-09-10 사용자 승인에 따라 다음 다섯 영역을 하나의 시각 언어로 정돈한다.

1. A-04 응원팀 선택 시 선택한 밴드가 무대 중앙으로 이동하는 카드 전환
2. A-06 예매 완료 시 티켓 인쇄·낙하·재등장·단발 반짝임 연출
3. P-05 정산 규칙 비율에 반응하는 양쪽 무대 조명 시뮬레이터
4. C-01 로그인 전용 헤더와 로그인 처리 중 브랜드 로더 보완
5. 공통 헤더·로더의 로고 크기, 간격, 좌표, 2.4초 키프레임 정합성 수정

기능 데이터, 정산 공식, API 계약, 라우팅 의미는 바꾸지 않는다. 새 모션은 정보를 대신하지 않고 현재 상태와 결과를 더 분명하게 보여주는 보조 표현이다.

## 2. 검토한 접근과 채택안

### A. 실제 DOM·SVG 기반 혼합 연출 — 채택

- Motion은 사용자가 직접 바꾸는 카드 위치와 조명 목표값을 처리한다.
- Anime.js는 티켓 발행과 로고처럼 순서가 정해진 단발 타임라인을 처리한다.
- 티켓, 글자, 금액은 실제 DOM·SVG로 남겨 접근성, 다국어, 반응형을 유지한다.
- 기존 vgpu 무대 효과는 지원 환경에서만 장식층으로 사용하고 CSS 정적 조명을 항상 제공한다.

장점은 실제 데이터가 그대로 보이고, 영상 없이도 선명하며, 각 효과를 독립적으로 테스트·제거할 수 있다는 점이다. 구현 복잡도는 세 안 중 중간이다.

### B. 사전 렌더 영상·Canvas 중심 연출

Apple 제품 영상과 가장 가까운 화질을 만들 수 있지만 공연·팀·예매번호가 바뀔 때 영상을 다시 만들 수 없다. 텍스트 접근성, 다국어, 저사양 폴백도 별도로 중복 구현해야 하므로 채택하지 않는다.

### C. CSS 전환만 사용하는 보수적 연출

번들과 유지보수는 가장 단순하지만 선택 카드의 연속적인 위치 이동과 발권 서사를 자연스럽게 연결하기 어렵다. reduced-motion 폴백으로는 사용하되 기본 경험으로 채택하지 않는다.

## 3. Apple 참고 영상에서 가져올 원칙

참고 페이지: <https://www.apple.com/kr/ipad-air/>

공식 페이지 소스에서 15개 비디오 요소를 확인했다. 동작은 첫 노출 1회 재생, 뷰포트 진입 시 재생·복귀 시 초기화, 모델 선택에 따른 전환, 사용자가 재생·일시정지·다시 재생할 수 있는 기능 데모로 나뉜다. 각 영상은 시작·종료 대체 이미지와 저사양 폴백을 가진다.

사용자가 제공한 `medium_2x.webm`은 VP9, 1200×2080, 30fps, 5초다. 약 0.9초에 피사체가 화면 아래에서 들어오고, 1.4~3.3초에 여러 겹으로 전개된 뒤, 3.7초 이후 최종 형태로 정착한다.

불러요에는 다음 원칙만 가져온다.

- 한 번에 주인공 하나만 움직인다.
- 시작과 끝 프레임은 정보가 완전한 정적 화면이다.
- 사용자가 결과를 보기 위해 애니메이션 종료를 기다리지 않게 한다.
- 다시 보기 수단을 제공한다.
- 뷰포트 밖 자산은 지연 로드하고 실패 시 최종 프레임을 즉시 표시한다.

제품 소개용 5초 영상을 거래 완료 화면에 그대로 복제하지 않는다. A-06은 확인 속도가 중요한 화면이므로 핵심 서사를 2.2초로 압축한다.

## 4. 공통 모션 아키텍처

의존 방향은 `app → pages → features → shared`를 유지한다.

```text
shared/motion
  motionPreferences.ts       모션 감소 감지와 공통 정책
  motionTokens.ts            spring, duration, easing 상수

shared/ui
  AnimatedBrandLogo.tsx      브랜드 SVG와 로고 재생 상태
  AuthHeader.tsx              로그인·온보딩 전용 얇은 헤더

features/ticket
  TeamChoiceStage.tsx         선택 카드 중앙 이동 표현
  IssuedTicketHero.tsx        실제 티켓 DOM과 발권 타임라인

features/studio
  SettlementLightStage.tsx    비율과 양쪽 조명 시각화
```

- 사용자가 조작하는 대상은 Motion의 중단 가능한 spring을 사용한다.
- 정해진 순서를 한 번 재생하는 대상은 Anime.js scope와 timeline을 사용한다.
- 숫자와 상태는 애니메이션 상태와 분리한다. 타임라인 실패가 저장·이동·결제 결과를 막지 않는다.
- 공통 상수는 필요한 값만 공유하고 각 화면의 전체 연출을 거대한 범용 컴포넌트로 추상화하지 않는다.

기본 이동 spring은 `type: spring`, `bounce: 0`, `duration: 0.4`다. 실제 드래그를 도입하지 않으므로 관성 bounce는 사용하지 않는다.

## 5. A-04 응원팀 선택 무대

### 동작

- 초기에는 기존 팀 목록을 그대로 보여준다.
- 팀을 선택하면 해당 카드가 `layoutId` 기반으로 목록에서 무대 중앙 프리뷰로 0.4초 동안 이동한다.
- 중앙 카드 뒤에는 선택 팀 포스터에서 유도한 두 개의 낮은 불투명도 조명이 켜진다.
- 다른 팀을 선택하면 현재 화면 값에서 바로 새 목표로 이동한다. 이전 애니메이션 완료를 기다리지 않는다.
- 목록의 원래 자리에는 동일 높이의 선택 자리표시자를 유지해 레이아웃이 접히지 않게 한다.
- 선택된 팀명은 주문 요약과 현재 radio 상태에 즉시 반영한다. 애니메이션이 데이터 갱신을 지연하지 않는다.

### 반응형

- 모바일: 중앙 프리뷰는 목록 위에 높이 168px 무대로 표시하고 카드 폭은 `min(72vw, 240px)`로 제한한다.
- PC: 좌측 선택 영역 상단에 높이 220px 무대를 두고 우측 주문 요약은 기존 sticky 구조를 유지한다.
- 팀이 한 곳뿐이어도 무대와 선택 상태가 정상 표시된다. 긴 팀명은 두 줄까지 허용하고 카드 폭을 늘리지 않는다.

## 6. A-06 티켓 발행 히어로

### 2.2초 타임라인

1. `0.00~0.55초` — 상단 발권 슬롯에서 실제 티켓 DOM이 아래로 펼쳐진다. `clip-path`와 `translateY`만 사용하며 공연명, 일시, 응원팀, 예매번호는 DOM에 처음부터 존재한다.
2. `0.55~0.85초` — 티켓이 슬롯에서 분리되고 2도 기울며 접촉 그림자가 떨어진다.
3. `0.85~1.15초` — 티켓이 화면 아래 경계 밖으로 낙하한다. 중간에 fade-out하지 않아 실제 물체처럼 보이게 한다.
4. `1.15~1.85초` — 티켓이 아래 대각선에서 다시 진입한다. 회전 `-18deg → 0deg`, scale `0.72 → 1`, 두 장의 저불투명도 잔상으로 속도를 표현한다.
5. `1.85~2.02초` — 최종 티켓이 중앙에서 critically damped settle한다.
6. `2.02~2.20초` — 티켓 테두리를 따라 빛이 한 번 훑고 우측 상단에 작은 별빛이 한 번 나타났다 사라진다.

### 반짝임 제한

- 반짝임은 1회이며 반복 pulse를 만들지 않는다.
- 화면 전체 밝기는 바꾸지 않는다. 티켓 테두리와 작은 12px 별빛만 사용한다.
- 섬광 위험을 피하기 위해 순백색 전체 면적 전환, 고대비 점멸, 3회 이상 반복을 금지한다.
- `prefers-reduced-motion: reduce`에서는 반짝임도 제거하고 180ms opacity 교차 전환으로 완성 티켓만 표시한다.

### 사용성

- CTA와 완료 정보는 DOM에 즉시 존재하며 애니메이션 중에도 포커스와 클릭을 막지 않는다.
- `Replay ticket / 티켓 다시 보기` 버튼으로 단발 타임라인을 다시 시작할 수 있다.
- 재생 중 다시 보기 버튼을 누르면 현재 표시값에서 안전하게 초기화한 뒤 재생한다.
- Anime.js 로드 또는 실행 실패 시 발권 슬롯과 잔상을 감추고 완성 티켓과 CTA를 즉시 표시한다.
- 모바일 티켓 폭은 `min(88vw, 420px)`이고 화면 전체 가로 스크롤을 만들지 않는다.

## 7. P-05 정산 비율 무대 조명

- Step 1 카드 위에 고정 분배와 관객 선택을 나타내는 두 개의 조명 영역을 둔다.
- 고정 분배는 인디고, 관객 선택은 핑크 조명으로 표현한다.
- 입력된 `fixedBp`와 `selectionBp`를 0~100%로 정규화해 각 조명의 폭, 중심점, 낮은 범위의 밝기에 1:1로 매핑한다.
- 사용자가 숫자를 입력하는 동안 목표값이 즉시 바뀌고 Motion spring이 현재 표시값에서 새 값으로 이어진다.
- 합계 오류, 빈 값, 범위 초과에서는 조명을 추정하지 않고 마지막 유효 비율을 유지한다. 합계 오류 문구가 정본이다.
- 정확한 bp와 예상 분배액은 기존 입력·표·패널을 그대로 유지한다. 조명만 보고 수치를 판단하게 하지 않는다.
- vgpu/WebGPU 미지원 또는 초기화 실패 시 CSS radial-gradient 조명으로 동일한 두 영역을 표시한다.
- 모바일 시뮬레이션 기본 접힘과 PC 2열 sticky 구조는 유지한다.

## 8. C-01 로그인 보완

화면설계 v6의 C-01은 전체 `AppHeader`가 아니라 서비스 타이틀과 언어 스위치만 있는 얇은 헤더를 요구한다. 따라서 검색·내비·프로필이 있는 전역 헤더를 붙이지 않는다.

- 현재 하드코딩된 `TICKR`를 `AnimatedBrandLogo` 기반의 확정 불러요 로고로 교체한다.
- 로그인·가입·지갑 온보딩에서 재사용할 `AuthHeader`를 만들고 로고, 언어 스위치, 선택적 뒤로가기를 책임지게 한다.
- 로고 클릭은 홈으로 이동하며 헤더 로고의 전체 애니메이션을 다시 시작한다.
- 소셜 버튼 3개, 최대폭 400px 카드, 모바일 20px 여백, 하단 탭바 없음은 명세 그대로 유지한다.
- 로그인 처리 중 전체 화면에는 작은 Spinner 대신 `BrandLoader`와 기존 상태 문구를 함께 표시한다. 실제 인증 완료를 2.4초 로고 때문에 지연하지 않는다.
- 오류가 발생하면 overlay를 즉시 닫고 기존 alert와 활성화된 소셜 버튼으로 돌아간다.
- 개발용 상태 선택기와 ThemeSwitch는 프로덕션 빌드에 포함하지 않는다.

## 9. 브랜드 로고 정합성

### 확인된 원인

- 확정 왼쪽 SVG는 한글과 마이크가 path지만 최종 `BULLEO`는 `<text>`다.
- 페이지는 Montserrat 400·500·700만 로드하면서 로고는 900을 요청해 합성 굵기가 적용된다.
- 현재 `BULLEO` 대문자 높이는 약 73 SVG 단위이고 `Y/O`는 118~129 단위여서 최종형이 작고 기준선이 다르다.
- 시작 로고와 최종 로고가 동일 viewBox 안에서 서로 다른 실제 경계를 사용해 전환 중 크기가 줄어 보인다.

### 수정 기준

- 팀이 확정한 왼쪽 `variant-a-merged-stem`의 외곽, 그라디언트, 핑크 지지대, 가로 그릴 한 줄을 유지한다.
- 최종 `BULLEO`를 글꼴 `<text>`가 아닌 SVG path로 고정한다.
- `BULLEO`, `Y`, `O`의 cap-height, optical baseline, 획 굵기를 하나의 좌표계에서 맞춘다.
- 시작 한글 로고, 중간 `불러YO`, 최종 `BULLEOYO`의 시각 중심과 외곽 높이를 동일하게 맞춘다.
- 키프레임은 설명 이미지의 `0.0, 0.4, 0.7, 0.9, 1.4, 1.7, 2.2, 2.4초`를 그대로 사용한다.
- 0.9~1.4초의 마이크 헤드 회전은 최종 O의 중심에 도달하도록 좌표를 실측한다.
- 1.7~2.2초에는 `Y/O`를 고정하고 `불러`와 `BULLEO` 접두부만 교차 전환한다.

### 헤더 재생 계약

- 한 문서 로드에서 첫 헤더는 마우스를 올리지 않아도 자동 재생한다.
- 일반 SPA 라우트 이동으로 헤더가 다시 마운트돼도 자동 반복하지 않는다.
- 브라우저 새로고침은 새 문서 로드이므로 다시 재생한다.
- 헤더 로고를 클릭하면 홈 이동과 동시에 전체 2.4초 타임라인을 다시 시작한다.
- 전체 재생이 끝난 뒤 hover/focus는 `Y/O`만 650ms 반응한다.
- reduced-motion에서는 최종 영문 로고를 정적으로 표시하고 클릭은 홈 이동만 수행한다.

## 10. 접근성·오류·성능

- 모든 효과는 `prefers-reduced-motion`을 따른다. 큰 이동은 짧은 cross-fade 또는 정적 최종 상태로 바꾼다.
- 모션 전후 읽기 순서, heading, radio, button, `aria-live` 계약을 유지한다.
- 포커스 가능한 요소를 투명도 0 상태로 장시간 숨기지 않는다.
- 애니메이션은 `transform`, `opacity`, 제한적인 `clip-path` 중심으로 구성한다. 입력 중 layout thrashing을 금지한다.
- Motion과 Anime.js는 사용하는 lazy route 청크에 남아야 한다. 로그인 헤더의 CSS 모션 때문에 Anime.js를 앱 셸에 정적 import하지 않는다.
- WebGPU, 동적 import, ResizeObserver 실패는 기능 실패로 전파하지 않고 정적 CSS/DOM으로 강등한다.
- 360×800, 390×844, 768px, 1440px에서 페이지 전체 가로 넘침이 없어야 한다.

## 11. 테스트와 시각 검증

모든 변경은 실패하는 테스트를 먼저 작성한다.

- 로고: `<text>` 미사용, 파트별 고정 path, 키프레임 시간, 문서 최초 자동 재생, SPA 재마운트 미재생, 새로고침 문서 식별, 클릭 재생, reduced-motion
- AuthHeader/Login: 확정 로고와 언어 스위치, 소셜 버튼 유지, pending BrandLoader, 오류 복귀, 홈 이동
- TeamChoice: radio 상태 즉시 반영, 선택 카드 중앙 프리뷰, 빠른 재선택, 단일 팀, 긴 팀명, reduced-motion
- BookingComplete: 2.2초 파트 계약, CTA 즉시 사용, 다시 보기, scope cleanup, 동적 import 실패 fallback, reduced-motion 정적 완료
- SettlementRules: 유효 비율 매핑, 입력 중 재목표, 오류 시 마지막 유효값, 0/100 경계, CSS fallback, 기존 계산 불변
- 회귀: 전체 Vitest, typecheck, lint, production build, route chunk 확인

Design Tools Lab에 다섯 효과의 대표 상태와 재생 버튼을 추가한다. Chromium에서 각 기준 시간의 스크린샷을 설명 이미지와 나란히 비교하고, 360·390·768·1440px, 키보드 전용, reduced-motion, light/dark를 확인한다.

## 12. 문서·인계

구현 중 아래 문서를 함께 갱신한다.

- `docs/frontend/STAGE_LEDGER_STATUS.md`: 적용·검증·남은 작업
- `docs/frontend/STAGE_LEDGER_DECISIONS.md`: 도구 선택과 motion/fallback 결정
- `docs/frontend/DESIGN_TOOL_EXPERIMENTS.md`: 재현 절차, 수동 QA, 롤백
- `CLAUDE.md`: 다음 작업자가 읽을 진입점

기록은 제안, 구현, 자동 검증, 브라우저 실측을 구분한다. Apple 페이지의 DOM·미디어 계약을 확인한 것과 모든 원본 영상을 실제 재생한 것을 혼동하지 않는다.

## 13. 범위 제외

- 실제 Apple 영상 또는 프레임을 제품 자산으로 복사하는 작업
- 음향 자동 재생과 진동
- 전 화면 반복 반짝임, parallax, cursor follower
- 정산 숫자의 count-up 또는 rolling animation
- 백엔드, 스마트 컨트랙트, API 응답 변경
- 로그인 명세에 없는 검색·내비·프로필을 C-01 헤더에 추가하는 작업

## 14. 완료 조건

- 다섯 영역이 승인된 동작과 정적 fallback을 제공한다.
- 로고의 모든 영문 글자가 path이며 시작·중간·완성형의 시각 높이와 중심이 일치한다.
- 티켓은 2.2초 안에 인쇄·낙하·재등장·단발 반짝임을 끝내고 사용자를 기다리게 하지 않는다.
- 선택 카드와 정산 조명은 사용자의 새 입력에 즉시 재목표된다.
- 로그인 전용 헤더가 확정 로고를 사용하고 처리 중 BrandLoader가 실제 인증 완료를 지연하지 않는다.
- 전체 자동 검증과 지정 뷰포트 수동 QA를 통과한다.
- 다른 작업자가 문서만 읽고 적용 상태, 검증 결과, 롤백 위치를 파악할 수 있다.

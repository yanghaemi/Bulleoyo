# 불러요 시각 연출 복원 디자인

- Jira: `S15P21B204-163`
- 상태: 디자인 승인, lab 비교 구현 진행

## 목적

현재 라이트 UI의 가독성과 정보 구조를 유지하면서, 기존 홈이 갖고 있던 공연의 무대감과 포스터 중심의 깊이를 선별 복원한다. 목표는 효과의 양을 늘리는 것이 아니라 불러요에만 필요한 대표 장면을 다시 만드는 것이다.

이번 단계는 운영 화면을 바꾸지 않는다. 개발 전용 `/__lab/design-refresh`에서 같은 콘텐츠로 세 가지 히어로 방향을 실제 크기로 비교하고, 선택된 방향만 후속 단계에서 홈·공연 상세·예매 흐름으로 확장한다.

## 확인한 현재 상태

| 항목 | 운영 배포 | 현재 lab | 판정 |
| --- | --- | --- | --- |
| 홈 첫인상 | 다크 배경, 대표 공연 캐러셀, 중앙 포스터 조명 | 라이트 배경, 평면 카드 목록 | 대표 장면이 미연결됨 |
| 카피 | `다음 무대를 만나는 곳`, `어떤 순간을 만나볼까요?` 등 감성 문구 | `공연`, `판매 중` 등 기능 문구 | 기능 문구를 기준으로 삼음 |
| 대표 공연 | `ShowCarousel`과 상세 진입 CTA | `HomeView.carousel`은 받지만 렌더하지 않음 | 데이터 계약은 남고 표현만 제거됨 |
| GPU·조명 | `StageFlare`/`HeroBackdrop`/CSS 폴백 사용 | 효과 컴포넌트 파일은 남아 있으나 홈에서 마운트하지 않음 | 삭제가 아니라 미연결 |
| 전역 배경 | `StageEffects`가 무대 라우트에서 동작 | 라이트 표면 위에서 약한 배경층만 보이거나 불투명 페이지에 가려질 수 있음 | 히어로와 전역 효과 책임 분리 필요 |

확인 근거:

- `frontend/src/features/performance/HomeScreen.tsx`는 `carousel`을 어댑터 호환용으로만 보존하고 카드 섹션만 렌더링한다.
- 같은 파일의 현재 미커밋 diff에는 `ShowCarousel`, `HeroBackdrop`, `StageFlare`, 대표 CTA가 제거된 흔적이 있다.
- `frontend/src/shared/fx/`의 WebGPU·Canvas·CSS 폴백 구현과 관련 테스트는 남아 있다.
- `motion`, `vgpu`는 이미 설치되어 있다. 이번 비교 구현에 새 제품 의존성은 필요하지 않다.
- 운영 배포는 데스크톱에서 대표 공연 무대를 확인했고, 현재 lab은 공개 HTTPS 미리보기에서 평면 목록을 확인했다. 아직 동일 데이터·동일 뷰포트 비교 캡처는 만들지 않았다.

## 공통 콘텐츠와 상호작용

세 시안은 동일한 대표 공연 데이터를 사용한다.

- 공연명, 날짜, 장소, 포스터, 공연 상세 링크
- 한 번에 선택된 공연 한 개
- 이전·다음 조작과 현재 위치 표시
- 자동 재생 없음
- CTA와 공연 정보는 첫 렌더부터 읽고 사용할 수 있음
- 포인터 모션 없이도 완성된 정적 구도
- `prefers-reduced-motion`에서는 이동·점등을 생략하되 조명 구도와 깊이는 유지
- GPU가 없거나 안전한 HTTPS가 아니면 CSS 표면·그림자 폴백 사용

## 시안 A — Light Stage

밝은 무대 표면 위에 포스터를 세우고 한쪽 상단의 광원이 포스터 가장자리, 뒷면, 바닥에 일관되게 닿는다. 기존 `HeroBackdrop`을 그대로 전체 배경에 펼치지 않고 대표 영역 안에서만 사용한다.

- 밝은 중성 표면과 방향성 있는 브랜드 조명
- 포스터 뒤의 접지 그림자와 얇은 가장자리 반사
- 첫 진입 시 500–700ms의 한 번뿐인 점등
- 호버에서는 포스터가 2–4px 들리고 가장자리 반사만 변화
- 흐릿한 보라색 원형 블러만 단독으로 사용하지 않음

## 시안 B — Concert Editorial

조명보다 포스터와 한글 타이포그래피의 편집적 대비를 전면에 둔다. 공연명·날짜·장소를 큰 잡지 지면처럼 배치하고, 포스터 선택이 바뀔 때 정보와 이미지가 짧게 교차한다.

- 비대칭 2열 구성과 선명한 타이포 계층
- 포스터 원색을 유지하고 주변 장식 색은 최소화
- 이전·다음은 작은 이모티콘이 아니라 충분한 터치 영역의 명시적 버튼
- 선택 전환 180–240ms, 전체 목록 순차 등장 없음

## 시안 C — Stage Window

라이트 서비스 화면 안에 대표 공연 영역만 국소적인 어두운 무대 창으로 만든다. 기존 `StageFlare`를 재사용하기 가장 적합하지만, 조명은 이 창 안에서만 동작한다.

- 페이지·검색·목록은 라이트 유지
- 대표 공연 창만 다크 표면과 볼류메트릭 조명 사용
- 창 경계가 명확하고 텍스트·버튼은 고정된 고대비 영역에 배치
- 내부 무대가 없는 화면으로 같은 효과를 복제하지 않음

## 구현 경계

- 새 실험 컴포넌트는 제품용 `HomeScreen`과 분리한다.
- `DesignRefreshPage`에 히어로 방향 선택 컨트롤과 프리뷰를 추가한다.
- 기존 `ShowCarousel`은 바로 수정하지 않고, 필요한 공통 데이터 타입과 접근성 계약만 재사용한다.
- GPU 컴포넌트에는 실험 전용 변형을 억지로 추가하지 않는다. A/C에서 필요한 범위가 기존 API로 불가능할 때만 작은 옵션을 추가하고 기존 기본값을 유지한다.
- 거래·인증·지갑·정산·운영 API는 호출하지 않는다.
- 실제 운영 라우트와 `HomePage`의 데이터 흐름은 이번 단계에서 변경하지 않는다.

## 검증

- Vitest로 세 시안 전환, 링크 대상, 활성 상태, 언어별 텍스트, reduced-motion 표식을 검증한다.
- 390px와 1440px에서 포스터·텍스트·버튼 겹침과 가로 넘침을 확인한다.
- GPU 사용 가능/불가 양쪽에서 핵심 콘텐츠가 동일하게 노출되는지 확인한다.
- 키보드로 시안 선택과 대표 공연 이동이 가능하고 포커스가 보이는지 확인한다.
- 시각 비교는 같은 fixture, 언어, 뷰포트로 캡처한다.

## 이번 단계에서 하지 않는 일

- 세 시안 중 하나를 사용자 선택 없이 운영 홈에 적용하지 않는다.
- 새 셰이더·애니메이션·UI 패키지를 설치하지 않는다.
- 전 페이지 디자인을 다시 덮어쓰지 않는다.
- 감성 문구를 되살리거나 새로운 슬로건을 만들지 않는다.
- 실제 구매·로그인·서명·환불 데이터를 만들지 않는다.

## 후속 승인 — 운영 홈 적용

2026-09-21 사용자 검토에서 세 방향 선택 UI 대신 하나의 편집형 구도를 유지하고,
활성 테마에 따라 밝은 `Light Stage`와 어두운 `Stage Window` 표면만 자동 전환하기로
확정했다. 이어서 같은 날 실제 홈 적용도 승인했다.

- `HomeScreen`이 이미 받는 `carousel` 데이터를 대표 공연 무대에 직접 연결한다.
- Jira 키, LAB 표식, 시안명, 디자인 설명은 제품 화면에 노출하지 않는다.
- 검색 또는 날짜 필터 결과가 비어 있으면 관련 없는 대표 공연도 함께 숨긴다.
- API·쿼리 계약과 자동 재생 금지 원칙은 그대로 유지한다.

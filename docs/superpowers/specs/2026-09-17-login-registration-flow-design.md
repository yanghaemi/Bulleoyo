# 소셜 로그인·신규 가입 분리 설계

## 1. 목적

현재 C-01 로그인 화면은 기존 회원도 로그인할 때마다 국가와 약관 동의를 다시 입력하게 한다. 이를 다음 원칙으로 바꾼다.

- 기존 회원은 소셜 버튼 한 번으로 로그인한다.
- 신규 회원에게만 최초 인증 뒤 국가와 필수 약관을 받는다.
- 가입 정보 제출 때문에 Web3Auth 팝업을 다시 열지 않는다.
- UI 언어는 한국어·영어 두 개를 유지하되 국가명은 각 국가의 자국어 명칭을 우선 표시한다.

비밀번호 로그인, 별도 이메일 가입, 소셜 제공자 추가, 지원 국가 확대는 이번 범위에 포함하지 않는다.

## 2. 검토한 접근과 채택안

### A. OAuth 전에 모든 사용자에게 가입 정보 입력 — 미채택

현재 방식이다. 백엔드 호출은 한 번이지만 기존 회원도 매번 국가와 약관을 입력해야 하고, 로그인과 회원가입의 의미가 섞인다.

### B. OAuth 뒤 전용 가입 필요 응답으로 분기 — 채택

첫 요청은 Web3Auth 신원 정보만 보낸다. 기존 회원이면 즉시 로그인하고, 처음 보는 신원이면 백엔드가 `AUTH_SIGNUP_REQUIRED`를 반환한다. 프론트는 이미 받은 Web3Auth 연결 정보를 메모리에 유지한 채 가입 정보 입력 화면을 열고, 제출 시 같은 신원 정보와 국가·약관을 함께 다시 보낸다.

API 호출이 신규 회원에게 한 번 늘지만 화면 의미가 명확하고, 오류 메시지 문자열에 의존하지 않으며, 기존 회원 경험을 가장 짧게 만든다.

### C. 프론트에서 소셜 식별자를 저장해 재방문 여부 추정 — 미채택

브라우저 저장소는 삭제·변조될 수 있고 다른 기기와 동기화되지 않는다. 회원 여부의 정본은 백엔드 데이터베이스로 유지한다.

## 3. 사용자 흐름

### 기존 회원

1. 로그인 화면에는 Google, Facebook, Kakao 버튼만 보인다.
2. 사용자가 제공자를 선택하면 Web3Auth 팝업을 한 번 연다.
3. 프론트가 `idToken`, 지갑 주소, 소셜 제공자를 `/auth/web3auth`에 보낸다.
4. 백엔드는 기존 회원을 찾아 세션을 발급한다.
5. 프론트는 기존의 지갑 온보딩·프로필·원래 목적지 라우팅 규칙을 그대로 적용한다.

### 신규 회원

1. 1~3단계는 기존 회원과 같다.
2. 백엔드는 회원을 만들거나 세션을 발급하지 않고 HTTP 409와 `AUTH_SIGNUP_REQUIRED`를 반환한다.
3. 프론트는 Web3Auth 연결 정보를 메모리에만 유지하고 국가·이용약관·개인정보 처리방침 입력을 표시한다.
4. 사용자가 가입 정보를 제출하면 팝업을 다시 열지 않고 같은 `/auth/web3auth` 요청에 기존 신원 정보와 가입 정보를 함께 보낸다.
5. 백엔드는 회원을 한 번만 생성하고 세션을 발급한다.
6. 성공 뒤 메모리의 `idToken`과 가입 임시 상태를 즉시 비운다.

사용자가 가입 단계를 취소하거나 페이지를 새로고침하면 임시 신원 정보를 폐기하고 최초 로그인 화면으로 돌아간다. `idToken`은 localStorage, sessionStorage, URL, 로그에 기록하지 않는다.

## 4. API 계약

`POST /api/v1/auth/web3auth`의 기본 요청 필드는 현재처럼 `idToken`, `walletAddress`, `socialProvider`다. `countryCode`, `termsAgreed`, `privacyAgreed`는 신규 가입을 완료할 때만 필요하다.

| 상황 | HTTP | code | 결과 |
| --- | --- | --- | --- |
| 기존 회원, 신원 유효 | 200 | 성공 | 토큰과 회원 정보 반환 |
| 신규 신원, 가입 정보 없음 | 409 | `AUTH_SIGNUP_REQUIRED` | 회원·세션·토큰을 만들지 않음 |
| 신규 신원, 가입 정보 유효 | 200 | 성공 | 회원 생성 후 토큰과 회원 정보 반환 |
| 신규 신원, 가입 정보 불완전·거짓 동의 | 400 | `COMMON_VALIDATION_FAILED` | 필드 오류 반환 |
| 잘못된 Web3Auth 토큰·주소 | 기존 인증 오류 | 기존 code | 기존 동작 유지 |

프론트 분기는 `msg`가 아니라 `code`만 사용한다. `AUTH_SIGNUP_REQUIRED`는 공통 오류 규격, 백엔드 `ErrorCode`, 프론트 오류 코드 타입, OpenAPI와 API v6 문서에 함께 추가한다.

동일 소셜 신원에 가입 완료 요청이 동시에 들어와도 한 회원만 생성되어야 한다. 고유 제약 충돌이 발생하면 트랜잭션 안에서 기존 회원을 다시 조회해 정상 로그인으로 수렴시키거나, 프로젝트의 기존 충돌 코드로 일관되게 응답한다. 중간 상태의 회원은 저장하지 않는다.

## 5. 프론트 상태와 화면

로그인 페이지는 다음 네 상태를 명시적으로 가진다.

```text
idle -> authenticating -> registrationRequired -> registering -> authenticated
                       \-> error             \-> error
```

- `idle`: 소셜 버튼만 표시한다.
- `authenticating`: 현재 공통 작업 오버레이에 소셜 인증·지갑 준비 중임을 표시한다.
- `registrationRequired`: 국가 선택과 두 필수 동의를 표시한다. 소셜 버튼은 숨기고 제출·취소를 제공한다.
- `registering`: 같은 연결 정보로 가입 요청을 보내며 팝업을 열지 않는다.
- 일반 오류: 오버레이를 닫고 현재 단계에서 재시도할 수 있게 한다.

Web3Auth 연결 객체 전체를 전역 저장소에 넣지 않는다. 가입 단계에 필요한 최소값인 `idToken`, 검증된 주소, 제공자만 LoginPage 생명주기 안에 둔다. 성공, 취소, 치명 오류, 언마운트 시 비운다.

## 6. 국가명 표기

브라우저의 `Intl.DisplayNames`는 하나의 선택 언어로 모든 국가를 번역하므로 자국어 표기를 만들 수 없다. 지원 중인 40개 국가에 대해 검토 가능한 정적 자국어 명칭을 둔다.

예시는 다음과 같다.

- KR `대한민국`
- JP `日本`
- CN `中国`
- TW `臺灣`
- DE `Deutschland`
- FR `France`
- ES `España`
- TR `Türkiye`
- IN `भारत / India`
- CH `Schweiz / Suisse / Svizzera`

옵션의 첫 줄은 자국어 명칭, 보조 줄은 현재 UI 언어의 국가명과 ISO 2자리 코드를 표시한다. 자국어와 번역명이 같으면 중복 이름은 생략한다.

```text
대한민국
South Korea · KR
```

목록 순서는 UI 언어를 전환해도 항목 위치가 바뀌지 않도록 자국어 기본명 기준으로 고정한다. 매핑에 없는 코드가 들어오면 현재 UI 언어의 `Intl.DisplayNames` 결과와 국가 코드로 안전하게 대체한다. 접근 가능한 `select` 이름과 제출 값은 기존 ISO 코드 계약을 유지한다.

## 8. 테스트와 검증

실패하는 테스트를 먼저 추가한다.

### 백엔드

- 기존 회원은 가입 필드 없이 로그인된다.
- 신규 신원은 가입 필드가 없을 때 `AUTH_SIGNUP_REQUIRED`이고 회원이 저장되지 않는다.
- 신규 신원은 국가와 두 동의가 있을 때 한 번만 생성된다.
- 불완전 가입 정보는 `COMMON_VALIDATION_FAILED`다.
- 동일 신원 재요청과 동시 요청이 중복 회원을 만들지 않는다.

### 프론트

- 최초 화면에 가입 입력이 없고 소셜 버튼이 즉시 활성화된다.
- 기존 회원 성공 시 가입 입력이 한 번도 나타나지 않는다.
- `AUTH_SIGNUP_REQUIRED`일 때만 가입 입력이 나타난다.
- 가입 제출은 `connectSocial`을 다시 호출하지 않는다.
- 취소·성공·언마운트 시 임시 신원 정보가 제거된다.
- 자국어 국가명이 UI 언어와 무관하게 유지되고 보조 번역만 바뀐다.
- 기존 로딩 오버레이, 사용자 취소, 지갑 온보딩과 목적지 복귀가 회귀하지 않는다.

### 통합

- 백엔드 DTO·오류 코드와 프론트 요청·분기 타입을 대조한다.
- OpenAPI 생성 결과와 API v6 표가 실제 구현과 일치하는지 확인한다.
- 백엔드 테스트, 프론트 단위 테스트, 타입 검사, 린트, 프로덕션 빌드를 실행한다.
- 로컬 HTTPS에서 기존 계정 로그인과 신규 계정 가입을 각각 수동 확인한다.

## 9. 완료 조건

- 기존 회원은 국가·약관을 보지 않고 한 번의 소셜 인증으로 로그인한다.
- 신규 회원만 인증 뒤 가입 정보를 입력하며 Web3Auth 팝업은 한 번만 열린다.
- 프론트가 오류 메시지 문자열에 의존하지 않는다.
- 가입 도중 토큰과 신원 정보가 브라우저 영구 저장소나 로그에 남지 않는다.
- 국가 선택기는 40개 지원 국가의 자국어 명칭과 ISO 코드를 일관되게 표시한다.
- 구현, 문서, 자동 테스트와 수동 HTTPS 검증이 동일한 계약을 설명한다.

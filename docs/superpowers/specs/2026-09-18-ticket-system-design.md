# 티켓 표현 통합 설계

작성일: 2026-09-18. 대상: `fix/fe/mvp-completeness`. 상태: 메인 세션에서 확정한 1차 구현 설계이며 구현·검증 완료 기록이 아니다.

## 목적과 범위

예매 완료·내 티켓 목록·티켓 상세가 같은 티켓으로 보이도록 외곽 형태와 재질, 정보 위계를 통합한다. 사용자 레퍼런스의 가로형 일렉트릭 블루 티켓을 기준으로 한다. 이번 하위 프로젝트는 티켓 표현과 상세 QR 확대에 한정한다. 인증·결제·권한·API 계약을 변경하지 않는다.

현재 화면 대응은 `_workspace/figma-screen-mapping-v2.md`의 D-11/L-11, D-12/L-12, D-12B/L-12B, D-13/L-13을 참고한다. 해당 문서는 화면 존재와 계약 차이의 근거이며 시각 일치 검수의 증거는 아니다. 후속 전체 UI 계획과 이번 명세를 합치지 않는다.

메인 세션은 별도 브라우저 확인으로 Figma D-13의 큰 티켓과 하단 정보 그리드를 확인했다. 원본의 왼쪽 큰 QR·오른쪽 바코드 배치 대신 사용자가 승인한 오른쪽 작은 QR·확대 보기 구성을 적용한다.

## 현재 진입점과 책임

아래 경로는 `frontend/src/` 기준이다.

| 화면 | 실제 경로와 컴포넌트 | 유지할 책임 |
| --- | --- | --- |
| 예매 완료 | `pages/BookingCompletePage.tsx` → `features/ticket/BookingComplete.tsx` → `IssuedTicketHero.tsx` → `TicketRevealStage.tsx` + `ConcertCollectorTicket.tsx` | 주문 응답 매핑, 완료 CTA, 기존 인쇄 연출 |
| 내 티켓 | `pages/MyTicketsPage.tsx` → `features/ticket/MyTickets.tsx` → `TicketStub.tsx` | 실제 상태 필터, 목록 선택·이동 콜백 |
| 티켓 상세 | `pages/TicketDetailPage.tsx` → `features/ticket/TicketDetail.tsx` + `TicketQr.tsx` | 소유권·상태에 따른 조회, 실제 사용 시각, 취소 가능 조건 |
| QR 조회 | `shared/queries/ticket.ts`, `shared/api/domains/ticket.ts` | 기존 서버 발급 토큰과 갱신 정책 |

`features/ticket` 안에 공용 도메인 표현 컴포넌트를 두고 `ConcertCollectorTicket`, `TicketStub`, `TicketDetail`이 재사용한다. 페이지는 API 데이터를 기존 화면용 값으로 연결하고, 표현 컴포넌트는 받은 데이터와 상태를 렌더링한다. 다른 `features/*` 도메인 간 교차 import를 추가하지 않는다. 목록 선택, 완료 화면 CTA, 취소 동작 등 기존 콜백 계약을 보존한다.

## 시각·정보 규칙

- 가로형 티켓, 둥근 모서리, 오른쪽 절취 스텁, 절취선 양끝 반원 노치가 모든 변형의 공통 외곽이다.
- 일렉트릭 블루 바탕, 큰 배경 타이포그래피, 얇은 분홍 타원 장식을 사용한다. 배경 글자·장식은 정보보다 뒤에 두며 접근성 트리에서 중복 낭독하지 않는다.
- 공연명·일시·장소·티켓 종류·실제 상태는 읽을 수 있어야 한다. 목록은 압축된 밀도, 완료·상세는 넓은 밀도로 조정하되 같은 형태와 재질을 유지한다.
- 사용 가능한 포스터 URL이 있으면 포스터 중심 변형을 적용하고, 글자가 놓이는 영역에는 대비를 확보하는 오버레이를 둔다. URL이 없거나 이미지 로딩이 실패하면 동일한 티켓 안에서 타이포그래피 변형으로 전환한다.
- 화면 폭에 맞춰 정보 배치를 조정한다. 전체 티켓을 축소해 본문과 QR이 함께 작아지는 방식으로 모바일 대응을 끝내지 않는다.
- 한국어·영어는 현재 선택 언어로 표시한다. 상태·대체 텍스트·QR 안내·확대/닫기 이름에도 같은 규칙을 적용한다.

## 데이터·상태 경계

실제 API에 존재하는 필드만 사용한다. 포스터를 위한 새 백엔드 필드나 업로드·티켓 아트 저장 기능을 만들지 않는다. `TicketSummary`·`TicketDetail` API 계약에는 `posterImageUrl`이 없으므로 초기 실데이터 목록·상세는 타이포그래피 폴백으로 표시한다. 현재 `BookingCompleteView`, `TicketListItem`, `TicketDetailView`의 선택 포스터 표현은 사용 가능한 상위 props가 실제로 제공하는 경우에만 지원한다. 응답에 없는 값을 타입 확장이나 임의 데이터로 채우지 않는다.

예매 완료의 `orderNumber`는 주문 식별자다. 개별 발급 티켓의 `ticketNumber`·`ticketId`와 바꿔 쓰거나 새 일련번호를 생성하지 않는다. 현재 완료 페이지는 주문의 `orderRef ?? orderId`, 상세 페이지는 실제 `ticketId`·`orderId`를 사용한다. 주문 완료 데이터만으로 개별 티켓의 사용 가능 상태를 단정하지 않는다.

상태는 `ISSUED → valid`, `USED → used`, `CANCELLED → cancelled`의 실제 계약을 따른다. 사용 완료·취소 티켓에 유효 배지를 고정 표시하지 않으며 QR을 숨긴다. `usedAt`이 있으면 공연 일시와 구별해 표시한다. 토큰 만료를 새로운 티켓 `EXPIRED` 상태로 만들지 않는다. 기존 취소 가능 여부와 소유권 처리를 유지한다.

## QR과 확대 보기

오른쪽 스텁의 작은 QR은 사용 가능한 티켓의 상세에만 표시한다. 목록·예매 완료에서는 QR을 요청하거나 꾸며 만들지 않는다. 서버의 `qrToken` 문자열을 접두어·JSON·URL 포장 없이 그대로 인코딩한다.

작은 QR은 클릭 또는 키보드로 확대할 수 있는 명확한 버튼이다. 확대 보기에는 같은 토큰으로 만든 같은 QR 데이터를 사용한다. 확대를 위해 두 번째 조회·갱신 타이머를 시작하지 않는다. 기존 `shared/ui/Modal.tsx`를 재사용하되 높이가 낮은 화면에서도 스크롤해 내용을 확인하고 닫을 수 있어야 한다. 접근 가능한 다이얼로그 이름, 열릴 때 포커스 이동, 내부 포커스 유지, Escape·닫기 버튼, 닫힌 뒤 트리거로 포커스 복귀를 제공한다. Modal의 안내·닫기 문구도 선택 언어를 따른다. QR 버튼과 닫기를 포함한 터치 영역은 최소 44px이다.

현재 `TicketQr.tsx`는 자체 타이머에서 `onRotate`를 호출하고 `shared/queries/ticket.ts`도 `refetchInterval`을 사용한다. 갱신 요청 소유권은 TanStack Query의 기존 `useTicketQr`로 유지하고, `TicketQr`의 자동 `onRotate` 호출은 제거한다. `TicketQr`는 카운트다운·표시만 담당한다. 작은 보기와 확대 보기는 그 수명주기를 함께 구독한다. 표시용 남은 시간 업데이트가 별도 갱신 요청을 발생시키거나, 확대를 여닫을 때 토큰 수명이 다시 시작되어서는 안 된다.

만료된 QR은 작은 보기와 확대 보기 모두 즉시 지우고 새 유효 토큰이 도착할 때까지 표시하지 않는다. 갱신 실패 때 이전 QR이 캐시 때문에 다시 나타나면 안 된다. 기존 응답의 `issuedAt`, `expiresAt`, `rotateAfterMs` 등 사용 가능한 수명 정보를 활용하고 새 API를 요구하지 않는다. 로딩·갱신 실패·생성 실패는 QR 영역에서 표현하며 티켓 정보 자체는 유지한다. 사용 완료·취소로 바뀌면 확대 화면 안에서도 QR을 남기지 않는다.

QR 여백은 현재 `margin: 1`에서 최소 4모듈의 quiet zone으로 맞춘다. 작은 QR과 확대 QR의 실제 스캔 가능 여부는 토큰 길이·화면 크기·기기 조건에 따라 수동 검증한다. 44px은 터치 영역 기준이며 QR의 충분한 스캔 크기를 보장하는 수치가 아니다. 자동 테스트나 화면 캡처만으로 모든 기기의 스캔 성공을 주장하지 않는다.

## 모션 보존

`shared/motion/motionTokens.ts`의 인쇄 1200ms + 정착 160ms = 총 1360ms 계약을 유지한다. 실제 티켓 DOM이 `TicketRevealStage`에서 인쇄되는 기존 구조를 보존한다. 회전·브랜드 뒷면·영상 전환·새 reveal을 추가하지 않는다.

1024px 미만 모바일과 reduced-motion에서는 실제 티켓을 즉시 표시한다. 모바일 replay 숨김과 reduced-motion replay 비활성화 계약을 유지한다. 완료 문구·내 티켓 보기·홈으로 CTA는 연출과 무관하게 첫 렌더부터 사용할 수 있다. 인쇄 상태를 결제·발권 상태로 사용하지 않는다.

## 인수 기준과 검증

동작 변경은 실패하는 테스트부터 작성하는 TDD로 진행한다. 다음 검증은 구현 후 수행할 항목이며 이 명세 작성으로 통과 처리하지 않는다.

1. 공용 표현과 각 어댑터: 실제 공연 정보·상태, 주문/티켓 식별자 구분, 목록·완료·취소 콜백, 선택 언어, 포스터 없음·로딩 실패 폴백을 검증한다.
2. QR: 서버 토큰 원문 인코딩, 4모듈 여백, valid 상세만 표시·조회, 새 토큰 전환, 만료 즉시 제거, 갱신 실패 시 이전 코드 차단, 확대 중 동기화, 중복 타이머·요청 없음, 키보드와 포커스 복귀를 검증한다.
3. 인쇄: 기존 `BookingComplete.motion.test.tsx`, `TicketRevealStage.test.tsx` 등의 1360ms·reduced-motion·즉시 사용 가능한 CTA 회귀를 확인한다.
4. `frontend/`에서 집중 테스트 후 전체 테스트·typecheck·lint·build를 실행한다. 메인 세션이 전달한 기존 전체 459개 테스트를 회귀 기준으로 삼되, 새 테스트 수와 실제 실행 결과를 별도 기록한다.
5. 브라우저에서 데스크톱 1440px·모바일 390px, 한국어·영어, 포스터 유무·실패, valid/used/cancelled, 긴 제목, QR 로딩·만료·실패·확대, 기본 모션·reduced-motion을 확인한다. 본문 잘림·수평 넘침·오버레이 대비·터치 영역·포커스 동작을 점검한다. 실제 QR 스캔은 별도 수동 결과와 미검증 기기 범위를 기록한다.

기존 QR 회귀 진입점은 `features/ticket/TicketQr.test.tsx`, `pages/TicketDetailPage.qr.test.tsx`다. 시각 결과를 사용자에게 검토 가능한 상태로 제시한다. 문서 작성·구현 과정 자체는 커밋·푸시나 외부 서비스 쓰기를 요구하지 않는다.

## 다음 묶음과 분리

후속 범위는 관객 화면, 회원·지갑, 스튜디오, 정산·관리자 등 기존 UI를 묶어 별도로 다룬다. 이번 티켓 명세는 그 화면들의 상세 설계·완료 판정이 아니다. `_workspace/figma-screen-mapping-v2.md`에서 구분한 기존 UI와 누락된 백엔드 계약을 계속 구별하며 업로드, 티켓 디자인 저장, 임의 판매 일정 등 없는 기능을 표시만으로 구현했다고 기록하지 않는다.

추가 결정 필요 사항은 현재 없다. 실제 QR 스캔, 브라우저 QA, 전체 회귀 결과는 구현 후 확인할 검증 항목으로 남는다.

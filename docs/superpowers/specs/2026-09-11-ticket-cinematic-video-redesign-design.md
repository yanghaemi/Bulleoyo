# A-06 대형 공연 티켓·시네마틱 발권 연출 설계

> **2026-09-11 구현 개정:** 아래의 사전 렌더 영상+DOM 하이브리드 제안은 실제 사용자 피드백 뒤 **실제 데이터 DOM 티켓 직접 회전**으로 대체됐다. 현재 정본은 `STAGE_LEDGER_DECISIONS.md`의 D-016이다. 5.2초 타임라인과 A 티켓 디자인은 유지하지만, 영상 교차 전환·autoplay·코덱·미디어 오류 계약은 더 이상 런타임 요구사항이 아니다. 기존 영상과 렌더러는 비교용 실험 자산으로만 보존한다.

## 1. 결정과 범위

2026-09-11 사용자 승인에 따라 A-06 예매 완료 화면의 기존 소형 티켓 카드를 대형 가로형 공연 티켓으로 교체한다. 시각 방향은 비교안 **A Concert Collector Pass**를 채택한다. B안의 홀로그램 재질은 섞지 않으며, 무광 블랙 인쇄물과 제한적인 브랜드 광택만 사용한다.

이 문서는 `2026-09-10-stage-motion-auth-polish-design.md`의 A-06 티켓 발행 설계를 대체한다. 다른 화면과 로고, 응원팀, 정산 조명, 로그인 설계는 기존 문서를 유지한다.

변경 범위는 다음과 같다.

1. 예매 완료 티켓의 정보 구조와 반응형 디자인
2. 인쇄·낙하·세로 재등장·느린 3D 회전·안착·반짝임으로 이어지는 5.2초 연출
3. 실제 데이터 DOM 티켓과 장식용 브랜드 뒷면을 연결하는 단일 3D 구조
4. 좁은 화면과 동작 줄이기 설정에 대한 정적 폴백
5. 재생·접근성·성능·테스트·다른 작업자 인계 계약

결제 처리, 예매 API, 저장 데이터, 라우팅, 백엔드 및 스마트 컨트랙트는 변경하지 않는다.

## 2. 채택한 접근

### 실제 DOM 티켓 + 장식용 브랜드 뒷면 — 최종 채택

공연명, 포스터, 예매번호, 결제 정보를 가진 `ConcertCollectorTicket`이 인쇄부터 최종 안착까지 같은 객체로 움직인다. 앞면이 카메라 반대쪽을 향할 때만 데이터 없는 브랜드 뒷면을 보여 준다.

이 구조를 채택한 이유는 다음과 같다.

- 회전 중 보이는 티켓과 최종 상세 티켓이 동일해 데이터·외곽·재질이 전환 시점에 달라지지 않는다.
- 공연명과 예매번호가 계속 DOM이므로 다국어, 접근성, 반응형과 실데이터를 유지한다.
- autoplay·코덱·네트워크 실패 경로와 영상 다운로드가 없어 발권 완료를 지연시키지 않는다.
- CSS transform·opacity·clip-path만 사용하고, 긴 티켓은 회전 중 축소했다가 가로 안착하며 확대한다.

### 검토 후 제외한 접근

- **영상만 사용:** 사용자별 실제 데이터를 표시할 수 없고 스크린 리더가 정보를 읽지 못해 제외한다.
- **사전 렌더 영상+DOM:** 이전 채택안이다. 회전 티켓이 실제 공연 티켓처럼 보여야 한다는 사용자 피드백에 따라 런타임에서 제외하고 실험 자산으로만 보존한다.
- **실시간 WebGL 렌더링:** 런타임 비용과 디버깅 범위가 예매 완료 화면의 가치보다 크므로 이번 범위에서는 제외한다.

## 3. 최종 티켓 디자인

티켓은 작은 카드가 아니라 완료 화면의 주인공이다. 데스크톱에서는 컨테이너 폭의 대부분을 차지하는 대형 가로형 공연 패스로 표시한다.

```text
┌──────────────┬───────────────────────────────────────────┬────────────┐
│ 공연 포스터   │ 상태 배지        공연명                    │ TKT · ADMIT │
│              │ 날짜 · 시각 · 장소                         │ ONE         │
│              │ 응원 밴드 · 예매번호                       │ 0041        │
│              │                                           │ QR/serial   │
└──────────────┴───────────────────────────────────────────┴────────────┘
                              점선 절취선 ────────────────────┘
```

### 크기와 비율

- 데스크톱: `width: min(88vw, 1180px)`, 목표 종횡비 약 `3.6:1`
- 태블릿: 컨테이너 폭 100%, 최소 높이를 유지하고 정보 간격을 축소한다.
- 모바일: 티켓을 가로 스크롤시키거나 축소해 읽기 어렵게 만들지 않는다. 포스터가 상단 배경으로 이동하는 모바일 전용 구성으로 재배치하고 세로 스텁은 하단 가로 스텁으로 바꾼다.
- 페이지 전체에는 어떤 뷰포트에서도 가로 넘침을 만들지 않는다.

### 영역 구성

- **포스터 영역 약 18%:** 실제 공연 포스터 URL이 있으면 사용하고 우측에 어두운 그라디언트를 덧댄다. URL 부재 또는 이미지 실패 시 공연 이니셜과 브랜드 그라디언트를 표시한다.
- **정보 영역 약 68%:** 사용 가능 상태, 공연명, 날짜·시각·장소, 응원 밴드, 예매번호 순서다. 공연명은 최대 두 줄이며 긴 값이 스텁을 밀어내지 않는다.
- **스텁 영역 약 14%:** 본체와 점선 절취선으로 구분하고 `TKT · ADMIT ONE`, 짧은 일련번호, 선택적으로 QR 또는 바코드 자리를 둔다.
- QR 값이 실제 입장용으로 확정되지 않은 동안 장식용 가짜 QR을 만들지 않는다. 대신 일련번호와 브랜드 마크를 쓴다.

### 재질과 색

- 기본 재질은 무광 블랙과 짙은 인디고다.
- 브랜드 핑크는 상태 배지, 작은 점, 절취선 주변의 제한적인 강조에만 사용한다.
- 테두리는 1px 저대비 선, 그림자는 넓고 부드러운 단일 그림자를 사용한다.
- 종이 노이즈는 2~3% 이하로 제한하고 텍스트 위에는 적용하지 않는다.
- 광택은 마지막에 한 번만 지나가며 지속적인 홀로그램, 무지개색, 반복 glow는 사용하지 않는다.

### 표시 데이터

DOM 티켓이 표시해야 하는 최소 데이터는 공연명, 공연 일시, 장소, 응원 밴드, 예매번호, 사용 가능 상태다. 현재 `BookingCompleteView`에는 포스터가 없으므로 `posterImageUrl?: string | null`을 선택 필드로 추가하고, 데모 흐름은 공연 상세의 확정 포스터 URL만 전달한다. 좌석·게이트·입장 번호가 실제 계약에 존재할 때만 추가한다. 존재하지 않는 값을 예시 문구로 꾸며서 노출하지 않는다.

## 4. 5.2초 시네마틱 타임라인

1. **0.00~0.70초 — 가로 인쇄:** 화면 상단 또는 무대형 슬롯에서 긴 티켓이 옆 방향으로 출력된다. 출력 진행 방향에만 미세한 종이 굴곡을 준다.
2. **0.70~1.20초 — 분리와 낙하:** 절취 접점이 풀리고 티켓이 2~4도 기울며 아래로 낙하한다. 중간 fade-out 없이 화면 경계를 완전히 벗어난다.
3. **1.20~1.50초 — 비어 있는 호흡:** 티켓이 사라진 짧은 정지 구간으로 다음 등장을 대비한다. CTA와 완료 문구는 계속 보이고 사용할 수 있다.
4. **1.50~1.90초 — 세로 3D 재등장:** 화면 아래 대각선에서 큰 티켓이 `rotateZ(-60deg) rotateY(-15deg) rotateX(10deg)` 자세로 날아온다. 가로 티켓의 긴 축은 수직선에서 약 30도 기울고 앞면은 계속 식별 가능하다. 2~3장의 반투명 잔상은 경로 뒤쪽에만 생기고 최종 티켓보다 선명해지지 않는다.
5. **1.90~4.80초 — 느린 회전과 안착:** Y축으로 한 바퀴 천천히 돌면서 `rotateZ(0deg)`의 가로 자세로 돌아온다. 이동·확대는 3.00초에 먼저 끝나고 Z축 정렬은 4.60초, Y축 회전은 4.80초에 끝난다. 과도한 bounce 없이 중앙에 정착하며 최종 프레임의 위치·비율·모서리 반경은 DOM 티켓과 동일하다.
6. **4.80~5.20초 — 실제 티켓 전환과 광택:** 영상 셸과 DOM 티켓을 400ms 동안 교차 전환한다. 사선 광택과 작은 별빛은 이 구간에서 한 번만 나타났다 사라진다.

Apple 참고 영상의 자산이나 프레임은 복사하지 않는다. 사용자가 제공한 영상은 다중 잔상, 전개, 안착의 시간감과 카메라 감각만 참고한다.

## 5. 컴포넌트와 자산 경계

```text
pages/booking/BookingComplete.tsx
  └─ features/ticket/IssuedTicketHero.tsx
       ├─ TicketRevealStage.tsx       재생 상태·영상·전환 조율
       ├─ ConcertCollectorTicket.tsx  실제 데이터·반응형 DOM 티켓
       └─ TicketReplayButton.tsx      명시적 다시 보기

public/media/ticket/
  ├─ ticket-reveal.webm               VP9 기본 자산
  ├─ ticket-reveal.mp4                H.264 호환 자산
  └─ ticket-reveal-poster.webp        첫/최종 상태 폴백 이미지
```

- `IssuedTicketHero`는 외부 공개 진입점과 예매 데이터 매핑을 유지한다.
- `TicketRevealStage`는 `idle | playing | settling | complete | fallback`만 관리하고 예매 상태를 소유하지 않는다.
- `ConcertCollectorTicket`은 애니메이션 없이도 완전한 티켓이어야 한다.
- 영상과 DOM의 외곽은 하나의 비율 토큰과 CSS 변수를 공유한다.
- 영상은 자막이나 의미 있는 정보를 담지 않는 장식이므로 `aria-hidden="true"`, 실제 정보는 DOM 티켓 한 벌만 접근성 트리에 남긴다.

## 6. 재생 계약

- 예매 완료 화면 첫 진입 시 한 번 자동 재생한다.
- 같은 화면의 단순 리렌더에서는 다시 시작하지 않는다.
- `Replay ticket / 티켓 다시 보기` 버튼을 누르면 처음부터 다시 재생한다.
- 재생 중 다시 누르면 기존 재생을 정리한 뒤 처음부터 시작한다.
- 새로고침은 새 문서 진입이므로 다시 재생한다.
- 애니메이션 재생 여부가 예매 성공 판정, 데이터 저장, CTA 활성화와 연결되지 않는다.
- 완료 제목, 예매번호와 CTA는 처음부터 DOM에 존재하고 포커스 가능하다.
- 자동 재생이 차단되거나 영상 `error`, `stalled`, 제한 시간 초과가 발생하면 즉시 `fallback`으로 전환해 완성 DOM 티켓을 표시한다.

## 7. 접근성·반응형·성능

### 접근성

- `prefers-reduced-motion: reduce`에서는 영상과 큰 이동을 재생하지 않고 180ms 이하의 opacity 전환 또는 즉시 완성 상태를 사용한다.
- 영상은 음소거·무음이며 오디오 트랙을 넣지 않는다.
- 반복 재생하지 않는다.
- 정보는 색과 움직임에만 의존하지 않으며 상태 배지에는 텍스트가 있다.
- 광택과 별빛은 1회만 사용하고 화면 전체의 밝기를 바꾸지 않는다.

### 성능

- 영상은 해당 lazy route에서만 필요하며 앱 셸 초기 번들에 포함하지 않는다.
- WebM을 우선하고 MP4를 호환 폴백으로 둔다.
- 자산 용량 목표는 WebM 3MB 이하, MP4 5MB 이하, poster 200KB 이하로 한다.
- 영상은 `preload="metadata"` 또는 화면 진입 시점의 제한적 preload를 사용한다. 결제 단계에서 미리 대용량 다운로드하지 않는다.
- DOM 전환 중 레이아웃 변경을 피하고 `transform`, `opacity` 중심으로 합성한다.
- `video.decode` 지연이 사용자의 완료 확인을 막지 않게 1.2초 내 재생 준비가 안 되면 정적 DOM으로 강등한다.

## 8. 오류와 폴백

- 예매 데이터 일부가 없으면 해당 행을 숨기되 공연명과 예매번호의 기존 폴백 계약은 유지한다.
- 포스터 실패 시 고정 비율 placeholder로 대체해 티켓 크기가 바뀌지 않게 한다.
- 영상 실패, 코덱 미지원, autoplay 거부, 탭 백그라운드 진입 시 완성 티켓을 보여준다.
- 페이지를 떠날 때 video와 Anime.js/Motion scope를 정리하고 예약된 timeout을 취소한다.
- 폴백에서도 다시 보기 버튼은 숨기거나 비활성화 이유를 접근 가능한 이름으로 알린다.
- 어떤 실패도 예매 완료 CTA, 홈 이동, 내 티켓 이동을 막지 않는다.

## 9. 테스트와 시각 검증

테스트는 구현 전에 실패하도록 추가한다.

- 티켓 정보 구조, 실제 값 노출, 존재하지 않는 좌석·QR 미표시
- 데스크톱 세 영역과 모바일 전용 재배치 클래스 계약
- 첫 진입 1회 재생, 리렌더 미재생, 다시 보기 재시작, cleanup
- WebM → MP4 source 순서와 poster 존재
- 영상 error, stalled/timeout, autoplay reject 시 즉시 DOM 폴백
- reduced-motion에서 video 미재생과 정적 DOM 노출
- 애니메이션 중 CTA 사용 가능 및 접근성 트리의 중복 정보 없음
- 전체 Vitest, TypeScript, ESLint, production build

수동 QA는 360×800, 390×844, 768×1024, 1440×900에서 수행한다. 각 타임라인 구간의 스크린샷과 최종 DOM 중첩 오차를 확인하고, Chrome과 Safari 호환 코덱 경로, 4배 CPU slowdown, 네트워크 차단, 키보드 전용, reduced-motion을 검증한다.

## 10. 제작 순서와 인계 기록

1. `ConcertCollectorTicket`을 정적 DOM으로 먼저 완성하고 반응형·접근성을 검증한다.
2. 같은 비율과 색으로 무기명 모션 셸을 제작한다.
3. WebM·MP4·poster를 생성하고 용량과 첫/마지막 프레임을 검증한다.
4. `TicketRevealStage`에서 영상과 DOM을 연결한다.
5. 오류·reduced-motion 폴백과 재생 버튼을 연결한다.
6. 자동 테스트와 브라우저 실측을 완료한다.

다른 작업 도구가 이어받을 수 있도록 다음 문서를 함께 갱신한다.

- `docs/frontend/STAGE_LEDGER_STATUS.md`: 구현 상태, 검증 결과, 남은 수동 QA
- `docs/frontend/STAGE_LEDGER_DECISIONS.md`: A안 채택, 영상·DOM 경계, 코덱·폴백 결정
- `docs/frontend/DESIGN_TOOL_EXPERIMENTS.md`: 자산 생성·재생·롤백 절차
- `CLAUDE.md`: 진입 파일과 필수 문서 링크

기록은 `제안`, `구현`, `자동 검증`, `브라우저 실측`을 구분한다. 렌더 영상을 만들었다는 사실과 실제 예매 데이터를 영상에 합성했다는 주장을 혼동하지 않는다.

## 11. 완료 조건

- A안 대형 가로 티켓이 데스크톱과 모바일에서 정보 손실·가로 넘침 없이 표시된다.
- 실제 데이터 DOM이 영상의 최종 프레임과 눈에 띄는 점프 없이 전환된다.
- 인쇄 → 낙하 → 비어 있는 호흡 → 세로·30도 기울기 재등장 → 느린 3D 회전과 가로 안착 → 단발 광택의 순서가 5.2초 안에 완료된다.
- 영상·코덱·자동 재생·네트워크 실패에서 즉시 완성 티켓으로 복구한다.
- reduced-motion, 키보드, 스크린 리더 기본 계약을 지킨다.
- CTA는 모션과 독립적으로 항상 사용할 수 있다.
- 자동 테스트, 타입 검사, 린트, 프로덕션 빌드와 지정 뷰포트 수동 QA 결과가 문서화된다.

# Stage Ledger 프론트엔드 결정 로그

이 문서는 코드만 보고 다시 추론하기 어려운 제품·기술 결정을 남긴다. Claude·Codex와 팀원은 구현 전에 이 문서와 설계 문서를 함께 확인한다.

## D-001. 시각 방향은 Stage Ledger

- 날짜: 2026-09-10
- 상태: 확정
- 결정: 공연 탐색은 다크 무대와 포스터가 중심이고, 예매·결제는 장식을 줄이며, 정산·검증·관리자는 고대비 중립 패널과 숫자 위계를 우선한다.
- 근거: 서비스의 감성적 발견 경험과 금융성 정보의 신뢰·가독성을 한 화면 문법으로 억지로 섞지 않기 위해서다.
- 상세: `docs/superpowers/specs/2026-09-10-stage-ledger-frontend-design.md`

## D-002. 팀 토큰이 정본이고 첫 진입 표시는 dark

- 날짜: 2026-09-08
- 상태: 확정
- 결정: 의미 색상·반경·글꼴 역할의 정본은 팀 토큰이다. 저장된 사용자 선택이 없는 첫 진입 표시는 `dark`로 연다.
- 근거: A-01 홈의 무대 조명과 포스터 대비가 어두운 바닥을 전제로 설계됐다. 토큰 정본과 초기 표시 테마는 서로 다른 책임이다.
- 코드: `frontend/src/shared/theme.ts`, `frontend/index.html`

## D-003. 숫자와 식별자 글꼴을 분리

- 날짜: 2026-09-08
- 상태: **대체됨** — 최신 `docs/design/14_디자인_토큰_v2.md`가 DM Mono 통일을 정본으로 확정
- 과거 결정: 금액·잔액·가격은 `Inter`, 예매번호·티켓번호·시각·주소·트랜잭션 해시는 `JetBrains Mono`를 사용한다.
- 근거: Inter와 `tabular-nums` 조합은 동적 금액의 폭 변화를 줄인다. JetBrains Mono는 `0/O`처럼 현장에서 읽고 받아 적는 값의 구분이 명확하다.
- 후속: 현재 코드에 남은 `font-num`·JetBrains Mono 사용은 디자인 토큰 v2 기준으로 별도 정리한다. 이 MR의 Stage Ledger·티켓 동작과는 분리한다.

## D-004. Meta·Apple 테마는 개발 전용

- 날짜: 2026-09-08
- 상태: 확정
- 결정: Meta·Apple은 비교 실험을 위해 유지하되 `ThemeSwitch`는 개발 빌드에서만 노출한다. 프로덕션 사용자의 진입점은 만들지 않는다.
- 근거: 실험 자산을 보존하면서도 제품의 공식 토큰과 사용자 설정 범위를 흐리지 않기 위해서다.
- 코드: `frontend/src/shared/ui/ThemeSwitch.tsx`

## D-005. 무거운 범용 시각 런타임은 추가하지 않음

- 날짜: 2026-09-10
- 상태: D-009의 제한적 예외와 함께 확정
- 결정: Paper Shaders, TypeGPU, Three.js, PixiJS, Rive, Spline, GSAP을 이번 고도화 범위에 추가하지 않는다.
- 근거: 현재 vgpu·CSS·브라우저 네이티브 API로 필요한 경험을 만들 수 있고, 번들·저사양·fallback 부담이 더 크다. Motion·Anime.js·Bklit은 책임을 좁혀 검증한 예외다.

## D-006. 실험 기능은 progressive enhancement

- 날짜: 2026-09-10
- 상태: 확정
- 결정: View Transition, CSS scroll-driven animation, Popover, vgpu 품질 조절은 지원 환경에서만 향상으로 적용한다.
- 필수 조건: 미지원, 초기화 실패, `prefers-reduced-motion: reduce`, 저성능 환경에서도 정보·탐색·예매 기능은 동일해야 한다.

## D-007. 예매 흐름의 정본 식별자는 URL의 ID

- 날짜: 2026-09-10
- 상태: 단계 A 적용, 단계 B 유지
- 결정: 주문 생성 전에는 `performanceId`, 생성 후에는 `orderId`를 정본으로 삼는다. 화면별 제목 상수로 흐름을 이어 붙이지 않는다.
- 현재 구현: 단계 A 데모 fixture는 `frontend/src/pages/demoBookingFlow.ts` 한 곳에서 공연 ID로 조회한다.
- 다음 구현: 단계 B에서는 같은 인터페이스를 실제 API·TanStack Query 데이터로 교체한다.

## D-008. 무대 효과는 탐색 라우트에만 마운트

- 날짜: 2026-09-10
- 상태: 적용
- 결정: `AmbientBackdrop`과 `StageBloom`은 홈, 공연 목록, 공연 상세에만 마운트한다.
- 제외: 주문·결제·지갑·스튜디오·검표·검증·관리자.
- 근거: 거래와 검증 화면의 가독성을 지키고 불필요한 Canvas/WebGPU 작업을 줄인다.

## D-009. 디자인 도구의 책임을 겹치지 않음

- 날짜: 2026-09-10
- 상태: 적용
- 결정: React 상태 enter/exit·팀 선택·비율 조명은 Motion, 브랜드 header·loader와 현재 A-06 실제 티켓 안무는 CSS, 수치 관계의 보조 표현은 Bklit이 맡는다. Anime.js A-06 실험은 현재 런타임에서 제거됐다.
- 금지: 같은 요소를 Motion과 Anime.js가 함께 소유하지 않는다. 차트가 정산 계산·반올림·불변식 판정을 맡지 않는다.
- 외부 도구: Manus 결과는 아이디어 후보일 뿐 코드·토큰·문서의 정본이 아니다.
- 근거: 도구별 제거·실패 경계를 분명히 하고, 실험이 제품 데이터 의미를 바꾸지 않게 하기 위해서다.
- 운영: `docs/frontend/DESIGN_TOOL_EXPERIMENTS.md`

## D-010. 브랜드 모션은 진입과 반응을 분리

- 날짜: 2026-09-10
- 상태: 왼쪽 A안 확정 벡터 적용, 클릭 상호작용과 객체 구조는 D-017이 대체
- 결정: 라우트 초기 fallback은 2.4초 서사를 한 번 사용한다. 헤더 최초 자동 재생의 단위는 **브라우저 문서**다. `sessionStorage['bulleoyo:header-intro-document']`에 boolean 대신 `String(performance.timeOrigin)`을 저장한다. SPA 재마운트는 완성형을 유지하고 새로고침은 새 문서로 재생한다. 로고 링크는 같은 경로에서 즉시, 다른 경로에서는 도착 헤더에서 재생하며 홈 이동을 지연하지 않는다. 당시 완성 뒤 hover/focus-visible 반응은 D-017의 클릭 양방향 전환으로 대체됐다.
- 구조: 당시 `불러`/`BULLEO` 접두부와 최종 `Y`·`O`를 독립 SVG 파트로 뒀으나, 마이크·마지막 O를 분리한 구조는 D-017의 단일 morph 객체로 대체됐다.
- 접근성: `prefers-reduced-motion: reduce`에서는 loader와 header 모두 **path 기반 최종 영문 워드마크**를 정적으로 보여준다. `matchMedia`가 없는 환경에서도 안전하게 렌더한다.
- 벡터 정본: 전달된 가로형 비교 SVG의 왼쪽 `variant-a-merged-stem`이다. 선택본은 `frontend/src/assets/brand/bulleoyo-logo-variant-a.svg`에 보존한다.
- 교체 경계: 후속 수정 SVG/Figma를 받으면 `data-part` 계약을 유지하고 도형만 교체한다.
- 글꼴 경계: 런타임 `<text>`를 쓰지 않는다. `pnpm gen:brand`가 Montserrat 윤곽을 생성하고 접두부·Y·O를 같은 cap-height와 optical baseline에 배치한다.

## D-011. 차트는 숫자와 표를 대체하지 않음

- 날짜: 2026-09-10
- 상태: 적용
- 결정: P-08 팀별 분배액 차트는 1280px 이상에서만 보이고 원본 표를 유지한다. M-03 발행량 구성 차트도 세 숫자 카드와 대사 결과를 유지한다.
- 실패 경계: ResizeObserver가 없거나 실제 차트 영역이 margin 합보다 작으면 차트를 렌더하지 않는다. 원 수치와 액션은 계속 사용할 수 있어야 한다.
- 근거: 금융성 수치의 정확한 판독은 텍스트가 담당하고, 차트는 비교 속도만 높여야 하기 때문이다.

## D-012. 모션이 선택·거래 결과를 소유하지 않음

- 날짜: 2026-09-10
- 상태: 상태 경계 원칙은 유지, A-06의 2200ms 모션 상세는 D-019로 대체됨
- 팀 무대는 장식 복제본이다. 실제 radio는 마운트를 유지하고 선택값과 주문 요약은 즉시 바뀐다.
- 티켓 데이터는 하나의 접근 가능한 article/dl에 남고 CTA를 잠그지 않는다는 원칙은 유지한다. 당시 2200ms 인쇄·낙하·잔상·sparkle 상세는 대체된 역사이며, 현재 A-06은 D-019의 1360ms print-only 계약을 따른다.
- 정산 조명은 bp를 소비하는 표현층이다. 유효값만 받아 빈 값·범위 초과·합계/서버 오류에는 마지막 유효 비율을 유지한다. 최초 invalid는 추정하지 않는다. 계산·저장 payload·오류 문구·숫자 애니메이션은 바꾸지 않는다.
- 조명은 CSS radial-gradient를 항상 제공한다. 새 WebGPU 의존성은 없으며 브라우저 GPU 가용성과 무관하게 정적 표현이 남는다.

## D-013. 로그인은 AuthHeader, 모달은 내부 포커스 유지

- 날짜: 2026-09-10
- 상태: implemented, automated verification, browser verified
- C-01은 브랜드·언어만 있는 AuthHeader를 사용한다. pending BrandLoader는 인증 완료를 기다리게 하지 않는다. 실제 인증 연결 여부는 별도 상태다.
- 400px 확인 모달의 긴 이중 언어 버튼은 세로로 배치하고 `role=group`을 제공한다. Tab/Shift+Tab은 모달 내부를 순환하며 Escape/닫힘은 opener로 복귀한다. 퇴장 DOM은 inert·aria-hidden으로 포커스를 받지 않는다. busy 상태는 dialog 자체에 포커스를 유지한다.

## D-014. 영상 참고와 검증 근거의 경계

- 날짜: 2026-09-10
- 상태: 기록 확정
- 제공된 5초 WebM을 프레임 샘플링했다. Apple iPad Air의 원본 미디어 계약·구조는 조사했지만 미디어 접근 불가로 15개 모두를 실제 재생하지 못했다. 한 주인공·완전한 시작/끝 상태·명시적 replay 등 구조적 모션 원칙만 재현했고 Apple 영상·자산을 복사하지 않았다.
- Lab은 고정 로컬 fixture와 제품 컴포넌트를 조합한다. 새 검증 코드가 production gate를 우회하지 않는다.
- 자동 테스트, 실제 브라우저 측정, matchMedia 대체를 통한 reduced-motion 확인은 별도 기록한다. Windows의 15px 세로 스크롤바와 Motion 개발용 reduced-motion 경고를 숨기거나 실패 없는 측정으로 바꾸지 않는다.

## D-015. A-06은 5.2초 장식 영상과 실제 DOM 티켓을 분리함

- 날짜: 2026-09-11
- 상태: 대체된 역사 — D-016을 거쳐 D-019로 대체됨
- 결정: 비교안 A의 대형 가로 공연 티켓을 실제 데이터 UI로 사용한다. 사전 렌더 영상은 같은 외곽의 데이터 없는 장식 프록시만 그리며, 4.80~5.20초에 실제 DOM 티켓으로 교차 전환한다.
- 시작 자세: 가로 티켓을 `rotateZ(-60deg)`로 세워 수직선에서 약 30도 기울이고 `rotateY(-15deg)`로 앞면을 남긴다. 1.90~4.80초 동안 Y축으로 천천히 한 바퀴 돌면서 `rotateZ(0deg)`로 가로 안착한다. 이동·확대는 3.00초에 먼저 끝나 회전이 느려져도 등장이 처지지 않는다.
- 반응형: 영상 전환은 1024px 이상에서만 보인다. 더 작은 폭에서는 같은 정보를 가진 반응형 DOM 티켓을 즉시 표시한다. 장식 효과 때문에 모바일 읽기 순서나 수평 스크롤을 희생하지 않는다.
- 실패 경계: autoplay·코덱·네트워크·`error`·`stalled`·startup timeout·reduced-motion은 모두 완성 DOM 티켓으로 끝난다. 결제 성공, 예매번호, CTA와 무관한 표현층이다.
- 근거: 영상에 사용자별 값을 굽지 않아 발권을 지연시키지 않고, 스크린 리더에는 실제 티켓 한 벌만 남기면서도 데스크톱에서 제품 필름 수준의 연출을 제공할 수 있다.

## D-016. A-06은 실제 데이터 DOM 티켓 자체를 회전함

- 날짜: 2026-09-11
- 상태: 대체된 역사 — D-015를 대체했으나 D-019로 다시 대체됨
- 결정: 사전 렌더 영상 프록시를 실제 완료 흐름에서 제거하고, `ConcertCollectorTicket` 한 벌을 `TicketRevealStage`의 3D 객체로 사용한다. 카메라 반대편에는 데이터 없는 브랜드 뒷면만 장식으로 둔다.
- 이유: 사용자가 보는 회전 티켓과 최종 상세 티켓이 동일한 공연·포스터·예매번호를 가져야 한다. 영상→DOM 교체 순간과 임시 실루엣의 이질감도 없어진다.
- 모션: 5.20초 인쇄·낙하·빈 호흡·`rotateZ(-60deg)` 재등장·느린 Y축 한 바퀴·가로 안착·단발 광택 계약을 유지한다. 재등장 뒤에는 회전·이동·깊이·확대를 같은 linear 진행률로 끝까지 이어 중간 정지감을 만들지 않는다. 긴 가로 티켓은 기울어진 동안 67~85% 크기로 무대 안에 유지하고 수평에 가까워질수록 100%로 확대한다. 재등장부터는 저채도 인디고·핑크 스포트라이트와 바닥 접지광이 티켓을 따라 서서히 열리고, 안착 직전에 얇은 타원 링이 한 번만 퍼진다.
- 경계: 모션은 결제·발권 상태를 소유하지 않는다. 조명·접지광·링은 모두 `aria-hidden` 장식이고 transform·opacity만 움직인다. 1024px 미만과 reduced-motion은 장식을 제거한 정적 티켓이며 CTA는 항상 사용 가능하다. 기존 영상 파일은 Lab/비교 자산일 뿐 런타임 계약이 아니다.
- fixture: 홈·목록·상세의 매진 예시는 `Busan Wave Festival`(`4`)이며 `IU Concert — The Golden Hour`(`5`)는 예매 가능이다.

## D-017. 헤더 로고는 한 객체로 양방향 안무를 순환함

- 날짜: 2026-09-11
- 상태: implemented, focused automated verification, browser frame verified
- 진입: 새 브라우저 문서는 기존처럼 2.40초 `불러요 → BULLEOYO` 정방향을 자동 재생한다. 이후 활성화는 3.00초 영문→한글 복귀와 2.40초 한글→영문 정방향을 번갈아 실행한다. 같은 문서의 SPA 재마운트는 `sessionStorage['bulleoyo:header-form']`에 저장한 안정 상태를 유지한다.
- 단일 객체: 마이크 헤드와 마지막 O를 별도 SVG로 교체하지 않는다. `morph-object` 한 벌의 외곽 비율, 중앙 aperture, 흰 grill을 바꿔 캡슐→O와 O→캡슐을 표현한다. 따라서 O와 마이크가 동시에 존재하지 않는다.
- 정방향: 헤드가 ㅛ에서 분리되어 오른쪽으로 구르고, aperture가 원형으로 열리며 grill이 줄어든다. O가 먼저 Y 오른쪽 자리까지 굴러가 안착한 뒤 ㅛ 지지대가 Y로 바뀌고, 이어 `불러`가 `BULLEO`로 전환된다. Y가 O보다 먼저 완성되지 않는다.
- 복귀: O가 2~3회 튄 뒤 오른쪽 경계를 벗어난다. 보이지 않는 구간에서 같은 객체가 캡슐로 바뀌어 왼쪽에서 재등장하고 글자 위를 여러 번 바운스한 뒤 ㅛ에 작은 마지막 점프로 안착한다. reverse 재생은 사용하지 않는다.
- 경계: 애니메이션 도중 추가 입력은 한 객체의 연속성을 지키기 위해 새 안무를 겹쳐 시작하지 않는다. 헤더 SVG는 overflow를 잘라 퇴장 객체가 검색·내비게이션 위를 지나지 않는다. reduced-motion은 영문 완성형을 정적으로 표시한다.

## D-018. 실제 발행 티켓은 Collector Foil A+ 실루엣을 사용함

- 날짜: 2026-09-11
- 상태: 실루엣·데이터 경계는 유지, 모션 조항은 D-019로 대체됨
- 결정: `ConcertCollectorTicket`의 데스크톱 외곽을 기존 `1280 / 422`에서 `13 / 5`로 바꿔 지나치게 얇은 목록형 인상을 줄인다. 포스터는 약 27% 영역을 사용하고 큰 공연명, 매트 블랙 바탕, 인디고·핑크 포일 외곽선, 절취 노치와 장식용 정품 실을 적용한다.
- 데이터 경계: 공연명·일시·장소·티켓 종류·응원팀·수량·결제 금액·예매번호·결제 시각은 기존 `BookingCompleteView`만 사용한다. 좌석·게이트·QR·바코드처럼 응답에 없는 값을 만들지 않는다.
- 반응형: 1024px 미만에서는 포스터·본문·스텁을 세로형 컬렉터 패스로 쌓고 모든 정보를 유지한다. 수평 스크롤을 만들지 않는다.
- 모션(대체된 역사): 당시에는 5.20초 인쇄·낙하·세로 기울기·느린 3D 회전·가로 안착을 유지했다. 이 조항의 카메라 반대편 브랜드 면·잔상 프록시·단발 광택은 D-019의 print-only 계약으로 대체됐다.

## D-019. A-06은 1360ms print-only 티켓으로 단순화함

- 날짜: 2026-09-14
- 상태: 현재 적용
- 결정: `TicketRevealStage`는 실제 `ConcertCollectorTicket` DOM을 프린터 슬롯에서 아래로 인쇄하고 짧게 정착시킨다. `TICKET_TIMING`은 인쇄 `1200ms`, settle `160ms`, 총 `1360ms`다.
- 제거: 현재 런타임에는 5.20초 타임라인, 3D 회전·기울기, 브랜드 뒷면, 잔상, Stage Halo·접지광·링, 영상 재생·DOM 교차 전환, 단발 광택·별빛이 없다. `render:ticket`은 현재 구현·재현 계약이 아니다.
- 반응형·접근성: 1024px 미만 모바일과 `prefers-reduced-motion: reduce`에서는 인쇄 애니메이션 없이 반응형 실제 티켓을 즉시 표시한다. 모바일에서는 replay를 숨기고 reduced-motion에서는 replay를 비활성화한다.

- 역사 보존: D-015의 영상→DOM 안, D-016의 실제 DOM 3D 회전 안, D-018의 5.20초 모션 조항은 삭제하지 않고 대체된 결정 이력으로 남긴다. D-018의 Collector Foil A+ 실루엣과 실제 응답 데이터 경계는 유지한다.

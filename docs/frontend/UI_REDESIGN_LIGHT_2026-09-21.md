# BULLEOYO 라이트 UI 승인 방향과 진행 현황

작성일: 2026-09-21
상태: **IN PROGRESS — 1차·결제·티켓·스튜디오 기본 화면 표현층 적용, 후속 화면·전체 QA 진행 필요**

이 문서는 [전 페이지 UI 리디자인 준비안](UI_REDESIGN_PREPARATION_2026-09-21.md)의 추가 결정과 현재 검증 범위를 기록한다. 준비안 원문은 보존한다. 아래 승인 방향 중 라이트 기본값과 1차 범위가 준비안의 다크 출발점·초기 단계 구분보다 우선한다. API·아키텍처·권한·거래 정책을 새로 정의하지 않는다.

## 승인된 방향

사용자는 2026-09-21 제품 UI를 **라이트 전용 기본 화면**으로 정리하는 방향을 승인했다. 전체 바탕은 오프화이트, 콘텐츠 면은 흰색, 주요 글자는 검정에 가까운 색으로 구성한다. 브랜드 보라색, 원래 BULLEOYO/‘요’ 로고, 파란 티켓의 정체성은 유지한다.

1차 구현 범위는 기존 **홈·공연 목록·공연 상세·MyPage·잔액 화면과 공통 컨트롤**이다. 실제 공연·금액·상태·다음 행동이 먼저 보이도록 정리한다. 큰 소개 문구, 반복 히어로, 모든 정보를 감싸는 카드와 장식은 줄인다. 이 범위의 진행을 전 페이지 구현 완료로 표현하지 않는다.

| 추가 피드백 | 반영 기준 |
| --- | --- |
| 캐러셀 화살표·점 | 캐러셀을 유지하는 경우 화살표의 클릭·터치 영역을 확보하고 SVG와 현재 위치 점이 배경 위에서 명확히 보이게 한다. 캐러셀 신규 도입을 뜻하지 않는다. |
| 잔액 숫자 | count-up을 제거한다. 데이터 도착 후 실제 잔액을 즉시 표시하고 로딩 중 가짜 0원을 표시하지 않는다. 실제 잔액이 0원인 경우와 미확인 상태를 구분한다. |
| 목록 행 화살표 | 행 오른쪽 경계와 충분한 안쪽 여백을 두고 텍스트·화살표가 겹치지 않게 한다. |

| 모서리 반경 | 입력·버튼·카드·티켓의 역할에 맞게 반경을 구분한다. 모든 요소를 같은 둥근 박스로 만들지 않는다. |
| 구분선 | 내부 구분선의 반복을 줄이되 전체 폭 헤더·푸터 경계는 유지한다. 콘텐츠 최대 너비와 외곽 선의 너비를 분리한다. |

## 테마 저장값 처리

기존 `b204.theme` 값은 삭제하거나 덮어쓰지 않고, 새 기본 테마를 결정할 때 무시한다. 새 키는 `b204.theme.light-v1`이다. 첫 화면과 저장소 접근이 차단된 환경에서도 라이트 기본값을 적용하는 방향이다.

새 키의 기억 기능은 개발자 비교 실험에만 사용한다. 일반 사용자용 테마 전환 버튼은 추가하지 않는다. 개발자 실험을 위한 비교 경로가 있다는 사실을 제품의 다크 모드 제공으로 해석하지 않는다.

## Figma의 미구현 화면 요청

사용자는 Figma에 있고 제품에 빠진 화면도 작업 범위에 포함해 달라고 요청했다. 실제 Figma 노드와 현재 라우트·컴포넌트를 대조해 빠진 화면과 상태를 먼저 확정해야 한다. **누락 화면 대조와 구현은 아직 완료로 기록하지 않는다.**

대조 결과가 있어야 후속 화면 목록과 구현 범위를 기록할 수 있다. 디자인에 보이는 데이터만으로 새로운 API나 가짜 응답·성공 상태를 만들지 않는다. 기존 준비안의 페이지 감사는 Figma 누락 화면 감사의 완료 근거가 아니다.

## 반영 내용

- 홈의 홍보형 히어로·캐러셀을 제거하고 실제 공연 목록을 우선 표시한다. 필터·빈 상태·재시도는 유지한다.
- 공연 카드는 한 벌의 DOM으로 모바일 가로형/데스크톱 세로형을 표시하고 본문 안쪽 여백을 확보한다.
- 상세는 일시·장소·가격·예매 가능 여부가 먼저 읽히도록 정리한다. 판매 제한 사유와 모바일 고정 예매 액션은 유지한다.
- MyPage 메뉴를 이용 내역/계정 설정/공연 운영으로 묶고 화살표를 안쪽에 둔다.
- 잔액 count-up·틸트·장식 막대를 제거한다. 확정 금액·처리 중 금액·조회 실패/재시도는 별도로 유지한다.
- 언어 선택은 글자를 움직이지 않고 배경 표시만 180ms 이동한다. reduced-motion이면 전환을 제거한다.
- 토스트 아이콘·본문·닫기를 정렬하고 닫기 이름을 선택 언어로 제공한다. 공통 버튼/닫기 영역은 44px이다.
- 라이브 이미지 누락은 중립색 폴백으로 표시한다. Lab의 샘플 포스터와 파란 티켓 아트는 제품 데이터로 오인하지 않도록 기존 샘플 표기를 유지한다.
- 인증·API·지갑 연결·체인 실행·권한·QR 만료 로직은 변경하지 않았다.

## 2차: 결제·내 티켓·티켓 상세

- 결제는 주문 내역/결제 수단 두 영역으로 정리했다. 장식 문구·번호·선택 배지를 제거하고 금액·잔액·다음 행동을 우선 표시한다. 기존 서명/실패/잔액 부족 상태와 호출부는 유지한다.
- 내 티켓은 모바일 1열, 데스크톱 2열이다. 티켓 선택 후 540ms 장식 대기를 제거해 상세 이동 콜백을 즉시 실행한다. 빈 목록에는 `/performances`로 이동하는 실제 링크를 제공한다.
- 티켓 상세의 등장/뷰 전환 장식을 제거했다. 파란 티켓, 포스터 대응, QR 확대·갱신·만료·사용/취소 상태는 기존 계약을 유지한다. 주문/티켓번호에는 별도 안쪽 여백을 적용했다.
- 예매 완료의 인쇄 연출은 별개로 유지한다. 실제 결제 성공이나 QR 발급을 샘플 화면으로 검증했다고 주장하지 않는다.
- TDD: 즉시 선택/빈 상태 링크 테스트가 수정 전 실패한 뒤 통과했다. 결제·티켓·QR·인쇄 연출 집중 검사 6개 파일/32개 테스트, 전체 145개 파일/1,053개 테스트 통과.
- 브라우저: 320px 결제 KO/EN, 내 티켓 EN, 티켓 상세 EN(만료 QR), 768px 상세 EN(샘플 QR 갱신), 1440px 결제 KO/내 티켓 EN 확인. 320px 결제·상세의 clientWidth/scrollWidth는 305/305px이다.

## 3차: 티켓 옵션·응원 팀 선택

- 티켓 옵션은 공연명·일시·장소를 하나의 정보 면에 모으고 티켓 종류, 잔여 수량, 가격, 수량, 합계를 순서대로 읽게 정리했다. 매진·가격 미확인·수량 상한의 기존 가드는 유지한다.
- 팀 선택의 중앙 포스터 이동 애니메이션과 장식 무대를 제거했다. 실제 라디오 목록을 바로 보여주며 선택이 정산에 반영되고 결제 후 변경할 수 없다는 기능 정보만 남겼다.
- 두 화면의 다음 단계 버튼에서 장식 화살표를 제거했다. A-03은 선택값만 넘기고 A-04 끝에서 주문을 한 번 생성하는 기존 데이터 흐름은 변경하지 않았다.
- 개발용 디자인 미리보기에 `티켓 선택 / Ticket options`, `팀 선택 / Team choice`를 추가했다. 샘플 데이터만 주입하며 API·결제 요청은 발생하지 않는다.
- 브라우저: 320px KO 티켓 옵션, 320px EN 팀 선택, 768px KO 팀 선택/주문 요약, 1440px KO 티켓 옵션/주문 요약을 확인했다. 모든 확인 너비에서 document clientWidth와 scrollWidth가 같았다.
- TDD: 장식 없는 정확한 버튼 이름과 제품 화면의 무대 제거를 수정 전 실패로 확인한 뒤 통과시켰다. 오래된 무대 컴포넌트와 모션 전용 테스트는 Git으로 복구 가능한 삭제 상태다.
- 미완료: 스튜디오·관리자 등 후속 화면, Figma 전체 누락 상태 대조, 실제 로그인·결제 E2E. 이 기록은 전 페이지 완료 보고가 아니다.

## 3.5차: 한 주문의 팀별 티켓 수량 배분

- 팀 하나를 라디오로 고르는 방식에서, 총 티켓 수를 참여팀별 수량 조절기로 나누는 방식으로 변경했다. `3장 중 3장 배분`처럼 현재 합계를 즉시 표시하며 전량 배분 전에는 주문 확인을 비활성화한다.
- 주문 요약은 `BULLEOYO × 1`, `Blue Hour × 2`처럼 팀별 수량을 모두 보여 준다. Lab fixture는 3장이라 분할 상태를 직접 확인할 수 있다.
- 현재 운영 API·DB·컨트랙트는 `chosenTeamId`와 `teamIndex` 하나만 받는다. 단일 팀에 전량 배분한 주문은 기존 결제를 그대로 호출하고, 여러 팀 배분은 잘못된 단일 팀 주문이나 다중 주문으로 변환하지 않고 구체적인 서버 연동 안내를 표시한다.
- 백엔드 전달 기준은 [팀별 티켓 수량 배분 연동 요청](./TEAM_TICKET_ALLOCATION_HANDOFF_2026-09-21.md)에 기록했다. 요청/응답, 합계 검증, 주문-팀 배분 저장, 티켓별 팀 귀속, 개별 환불, 컨트랙트 V2, receipt 대조와 완료 조건을 포함한다.

## 5차: 라이트 홈 WebGPU 실험과 제외 결정

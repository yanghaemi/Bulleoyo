# 팀 관리·초대·규칙 동의·공연 이미지 점검

기준: 2026-09-22, 작업 브랜치 `feat/fe/performance-media`. 현재 작업 파일과 fetch한 `origin/develop`(fc20b73)을 대조했다. 기존 미커밋 디자인 변경은 유지했다. 이 문서는 배포 완료 보고가 아니다.

## 이번 반영

- 팀 관리: 팀 ID와 복사 버튼, 리더 역할을 명시한다. 팀 목록에도 ID를 표시한다.
- 팀 나가기: API가 없으므로 버튼은 비활성화하고 이유를 바로 표시한다. 공연 참여팀 제외 API를 팀 탈퇴로 사용하지 않는다.
- 참여팀: 성공 응답을 받은 초대·수락·제외 결과를 현재 화면에 남긴다. 실패/진행 중은 성공으로 쓰지 않으며, 동시 중복 작업을 막는다. 화면을 떠나면 사라지는 최근 처리 결과이지 영구 이력이 아니다.
- 초대 목록: 서버가 반환한 내 팀 초대 행을 모두 조합한다. 주최팀·내 팀·팀 ID를 명시한다. 서버가 생략한 초대는 복구할 수 없다.
- 대시보드: 처리할 일의 시각적 우선순위를 높이고 알림·상태 새로고침을 제공한다. 초대·제외 성공 시 공연 목록 캐시도 갱신한다. 공연 목록은 `pageInfo`에 따라 이전·다음 페이지를 이동하며, 공연 수와 할 일 수가 현재 페이지 기준임을 KO/EN으로 명시한다. 별도 주기 폴링이나 전역 알림 수 추측은 추가하지 않는다.
- 규칙 동의: 서버가 선택한 `myAgreement.teamId`와 팀 이름·상태를 상단에서 보여 준다. 서명 중/확인 중/서버 동의 완료를 구분한다.

## Figma와 생성 흐름

브라우저에서 `WEB · 다크 + 로딩`의 D-23, D-24, D-24A를 직접 확인했다. MCP는 호출 한도로 사용할 수 없었다. 전체 프레임을 모두 검수했다는 뜻은 아니다.

| 화면 | 현재 상태 | 남은 작업 |
| --- | --- | --- |
| D-22 공연 정보 | 기존 생성 폼 존재 | 승인된 단계별 생성 흐름으로 통합 |
| D-23 포스터 편집 | Lab 화면 구현: 3:4 자르기·확대·회전·위치 조정 | 실제 업로드/영속 저장/생성 폼 연결 |
| D-24 티켓 직접 디자인 | Lab 화면 구현: 5:2 이미지·색상·제목·일시·장소 | 업로드 결과를 생성 요청에 연결 |
| D-24A 티켓 이미지 업로드 | Lab에서 모드 전환·이미지 미리보기 | 업로드 API 연결 |
| D-25 티켓 옵션 | 기존 폼에 옵션 입력 존재 | 단계 이동 시 입력 유지 및 최종 확인 연결 |
| D-26 판매 일정 | 기존 승인 설계에서 별도 입력 제외 | 서버 계산 정책 유지; Figma만 보고 재도입하지 않음 |
| D-27 최종 확인 | Lab 화면 구현: 공연·포스터·티켓 이미지·티켓 옵션 요약, 섹션별 수정 복귀 | 실제 미디어 ID/옵션을 한 번만 제출하는 라이브 생성 흐름 연결 |

Lab의 이미지 편집 결과는 실제 공연에 저장되지 않는다. 저장 콜백이 없는 상태에서는 저장 버튼을 비활성화하고 안내한다. 실제 생성 폼에도 미디어 미연결 사실을 표시한다. QR·티켓 상태·티켓 번호는 정적 디자인 이미지에 가짜로 넣지 않는다.

정본은 승인된 `docs/superpowers/specs/2026-09-21-performance-media-creation-flow-design.md` 및 media frontend/backend 계획이다. 파일 API 계약은 미정이 아니라 **설계 승인 후 구현·병합되지 않은 상태**다. Figma 파일 크기 문구와 충돌하면 승인된 계약의 출력 제한(5 MiB)을 따른다.

## 백엔드에 전달할 내용

아래는 그대로 전달 가능하다.

```text
팀 관리/초대/규칙 동의와 공연 이미지 연결 확인 부탁드립니다.

1. 팀 나가기
현재 TeamController에는 생성/내 팀 조회/상세/수정만 있고 탈퇴 API가 없습니다.
또 현재는 리더 중심 모델이라 일반 멤버 탈퇴인지, 리더 이전인지, 팀 해산인지 정책이 필요합니다.
진행 중 공연·미정산금·보증금이 있을 때의 제한까지 정한 뒤 계약 부탁드립니다.
프론트는 임의 삭제 대신 비활성 버튼과 사유를 표시했습니다.

2. 보낸 초대와 상태
공연 상세 participants는 ACCEPTED만 반환하고, 보낸 INVITED를 다시 조회할 API가 없습니다.
주최자가 초대 직후 새로고침하면 사라진 것처럼 보입니다.
권한 검사된 참여팀 조회에 teamId/name, INVITED/ACCEPTED, invitedAt/acceptedAt을 제공해 주세요.
취소/거절/제외 이력이 필요하면 상태와 조회 범위를 별도로 합의해야 합니다.
현재 프론트의 처리 결과는 해당 화면에서 받은 성공 응답만 보관하며 영구 이력을 대체하지 않습니다.

3. 여러 내 팀으로 참여한 공연
PerformanceService.myPerformances는 공연당 한 행이며 내 팀 중 첫 팀 또는 주최팀을 선택합니다.
반면 RuleService의 myAgreement는 내 팀을 순회하며 마지막 팀으로 덮어쓰는 구조입니다.
따라서 목록에서 본 팀과 동의 대상 팀이 달라질 수 있습니다.
공연별 내 참여팀 배열 또는 팀별 행을 제공하고, 규칙 조회/prepare/서명 대상도 명시적 teamId로
일관되게 선택·권한 검증할 수 있도록 계약을 정리해 주세요.
프론트는 현재 서버가 반환한 동의 대상 팀 ID를 명시하지만 누락된 팀 선택까지 해결된 것은 아닙니다.

4. 포스터/티켓 이미지
이미 승인된 performance-media 설계의 POST /api/v1/files와
posterUploadId/ticketArtworkUploadId, 조회용 이미지 URL 연결이 최신 develop에 없습니다.
TEMP 파일 만료/소유권/이미지 검증/저장소까지 해당 설계대로 구현 후 알려 주세요.
프론트의 3:4 포스터와 5:2 티켓 이미지 편집기는 Lab에 준비했으며 실제 저장 성공으로 표시하지 않습니다.

5. 발급 티켓 artwork 조회
ticket_03 OrderDetail, ticket_04 TicketSummary, ticket_05 TicketDetail 응답에는
posterImageUrl과 ticketImageUrl이 모두 없습니다. 이 상태에서 내 티켓마다 performance_03을 추가 호출하면
N+1 요청이 되므로 프론트는 우회 조회를 넣지 않았습니다. 세 응답 DTO와 OpenAPI에
posterImageUrl 및 승인된 별도 artwork가 있다면 ticketImageUrl을 선택 필드로 추가해 주세요.
프론트는 계약 반영 뒤 ticketImageUrl ?? posterImageUrl 순서로 연결하겠습니다.

6. 전역 처리할 일 집계
performance_06의 pageInfo로 공연 페이지 이동은 구현했습니다. 다만 수락 대기 초대, 규칙 동의,
보증금·입금 등 계정 전체 처리할 일 합계와 unread 상태는 응답에 없습니다.
전역 배지가 필요하면 모든 페이지를 백그라운드 순회하지 않도록 별도 summary 계약 또는 집계 API를 제공해 주세요.
```

## 남은 검증·제한

최종 로컬 검증: 전체 테스트 154개 파일 / 1,104개 통과, typecheck·ESLint·프로덕션 빌드·diff-check 통과. 빌드에는 의존성의 querystring 외부화 및 큰 청크 경고가 남는다. 브라우저에서 375px 팀 정보와 ID 복사, 티켓 디자인/업로드 모드 왕복 입력 유지, D-27 요약과 포스터 수정 복귀, 포스터 미연결 안내를 확인했다. 이미지 파일 처리/렌더링/콜백 실패는 자동 테스트로 확인했으며 브라우저 파일 업로드는 미실행이다.

- 대시보드는 공연 목록을 페이지 단위로 탐색할 수 있다. 전체 미처리 알림 수/읽음/영구 이력은 구현하지 않았으며 전용 집계 API가 필요하다.
- 실제 계정 초대→상대 수락→규칙 서명→체인 확정과 이미지 업로드 E2E는 미실행이다.
- 운영 배포·MR·Jira 업데이트는 이번 로컬 변경과 구분해 진행해야 한다. 기존 -99/API 및 미디어 설계 작업과 연결하되 새 이슈 번호를 만들어서 적지 않는다.
- 모든 Figma 화면의 누락 여부, 생성 위저드 통합, 계약 연결은 남은 작업이다. Lab 화면 존재를 실제 기능 완료로 집계하지 않는다.

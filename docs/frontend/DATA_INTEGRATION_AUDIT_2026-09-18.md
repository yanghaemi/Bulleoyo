### 기존 주문 상세 API의 조회 한계

주문 상세에는 `resumable`·`expiresAt`이 없다. R1 수정은 목록에서 이미 관측한 값을 주문별로 보존해 페이지 변경 후에도 재개 판단에 사용한다. 현재 서버가 준 `resumable: false`, 상세의 `PAID`·`PAYING`, 렌더 시점에 만료된 `expiresAt`이 이전의 재개 가능 판단보다 우선한다.

현재 목록 페이지 밖의 주문에 직링크로 들어왔고 해당 주문의 목록 값을 한 번도 관측하지 않았다면 재개 가능 여부는 unknown으로 남겨 재개를 허용하지 않는다. 이는 기존 상세 API의 정보 부족으로 남은 계약 확인 항목이며, 신규 BE 필드를 제공하거나 모든 직링크 재개를 해결했다고 보지 않는다.

## MR !145 생성 후 추가 리뷰 반영

주문 목록의 `flatMap`은 새 배열을 만들므로 원본 쿼리 캐시를 변경한다는 지적은 재현되지 않았다. 다만 현재 페이지 밖의 선택 주문을 목록에 삽입하여 20개 페이지가 21개 행으로 표시되는 문제는 재현했다. `selectedOrder` prop으로 페이지 행과 영수증을 분리하고, 모바일의 페이지 밖 상세 보기·닫기를 처리했다. 목록이 loading/error 상태여도 독립된 영수증을 유지한다.

`TicketOptions`의 조건부 수량 보정은 제한된 범위에서 수렴하므로 프로덕션 로직은 유지했다. 재고 감소 후 증가해도 이전 수량이 되살아나지 않는 경우와 재고 0에서 진행을 차단하는 경우의 회귀 테스트를 보강했다.

추가 변경만 독립 검토한 결과 신규 P1/P2 문제는 확인되지 않았다. 집중 검증은 **4파일/26테스트 통과**다. 추가 수정을 포함한 2026-09-18 17:40:18 시작 `pnpm test`는 **137파일/991테스트 통과**(exit 0, 96.95초)했다. `pnpm typecheck`·`pnpm lint`·`pnpm build`도 모두 exit 0이며(빌드 29.16초), 변경한 프론트엔드 4파일의 Prettier 검사와 `git diff --check`는 통과했다. 위 1차 MR HEAD의 988테스트 결과와 구분한다. 원격 CI는 로컬 검증과 별도로 확인한다.

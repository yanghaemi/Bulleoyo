### 3.1 디자인 토큰 (목업 → Tailwind `@theme`)

> **⚠ 2026-09-08 폐기 — 토큰 정본은 [`14_디자인_토큰_v2.md`](./14_디자인_토큰_v2.md)다.** 아래 amber `@theme`는 9/3 목업 시안을 그대로 옮긴 임시값이었고(UI/UX 확정값 아님), 신현경이 9/8 blue 기반으로 확정하면서 대체됐다. amber는 Warning 전용 색으로만 남는다. 이 절의 **규칙**(역할 이름만 사용, `--color-` 접두 리네임, 모션 규칙)은 유효하며 문서 14 §3에 그대로 계승됐다. 블록은 이력 보존용으로 남긴다.


```css
@import "tailwindcss";
@theme {
  --color-amber: #e39b2b;   --color-amber-deep: #8a5510;
  --color-amber-soft: #fbf1de; --color-amber-line: #efdcb8;
  --color-ink: #17141f;     --color-ground: #f5f3f7;
  --color-line: #e3dfe9;    --color-muted: #6f6880;
  --color-ok: #2e7d5b;      --color-ok-soft: #e4f1ea;
  --color-crit: #b3243c;    --color-crit-soft: #fbe7ea;
  --font-display: "Archivo", "Noto Sans KR", sans-serif;
  --font-body: "Noto Sans KR", sans-serif;
  --font-mono: "IBM Plex Mono", monospace;
  --breakpoint-md: 48rem;   /* 768px — 유일한 분기 */
}
```

역할 이름(`amber`, `crit`, `surface`)만 쓰고 팔레트 이름(`purple-500`)은 쓰지 않는다. 프레스 `scale(.97)` 160ms `cubic-bezier(.23,1,.32,1)`, 호버는 `(hover:hover) and (pointer:fine)` 게이트, `prefers-reduced-motion` 존중 — 목업 규칙 그대로.

목업(`docs/design/mockup/`)은 `--ink`·`--amber`·`--crit`·`--ground`·`--line`·`--muted`·`--ok` 등 접두 없는 변수명을 쓴다. Tailwind v4는 `--color-*` 네임스페이스여야 `text-ink`·`bg-amber` 유틸리티가 생성되므로 이전 시 `--ink → --color-ink`처럼 **`--color-` 접두를 붙여 리네임**한다(이 `@theme` 블록이 정본). 목업이 참조하는 `support.js`는 저장소에 없다 — 목업 전용 스크립트라 이전 대상이 아니다.

### 3.2 구조와 의존 방향

```
src/app(providers·router·error) → pages → features → shared(api·blockchain·ui·i18n·config)
```

- features는 도메인 13개 코드로: `member` `team` `wallet` `performance` `rule` `ticket` `payment` `coin` `refund` `entry` `settlement` `verify` `admin`
- shared는 상위를 import하지 않고, features끼리 직접 import하지 않는다. 조합은 pages에서.
- 지갑 SDK는 화면에서 직접 호출하지 않고 `shared/blockchain/WalletAdapter`를 거친다.
- API 클라이언트는 `{code, data, msg}`의 `code`만으로 분기한다. 401 refresh는 `refreshPromise` 공유로 단일 실행.
- `senderSignedRlp`·개인키·시드는 localStorage·로그·에러 리포트에 남기지 않는다. 컨트랙트 주소·chainId는 `shared/config` 한 곳.

## 5. PoC 체크리스트 (W3 첫 3일, Jira -14 스파이크에 포함)

1. Web3Auth v10 Modal이 React 19에서 설치·로그인·프로바이더 반환 되는가
2. Web3Auth 프로바이더 키로 `@kaiachain/ethers-ext/v6`가 FeeDelegatedSmartContractExecution 발신자 서명 RLP를 만드는가
3. Kaia Wallet 확장에서도 같은 RLP가 나오는가 (실패 시 외부 지갑 P1 하향 = 방안 C)
4. Spring Boot 3.5 + web3j-ext v2.0.7이 okhttp 충돌 없이 기동하는가
5. 서버 web3j-ext가 RLP를 디코드해 fee payer 서명 후 Kairos 전송·receipt 수신이 되는가. 발신자 KAIA 잔액 0에서도 성공하는가
6. Flyway 11 + flyway-mysql로 ERD v5 SQL이 적용되고 `@Enumerated(STRING)`로 ENUM 컬럼을 읽는가

1~5가 되면 스택 확정. 2는 되고 3이 안 되면 방안 C. 2가 안 되면 지갑·연동 층을 다시 짠다.
